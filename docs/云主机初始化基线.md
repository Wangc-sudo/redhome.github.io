## §1. IPv6 出网卡死防护（三级，换机零遗留）

**背景**：2026-09-22 dops-app 事故——ECS 带 IPv6 地址、DNS 默认 AAAA 优先，
但 VPC 无公网 IPv6 出网，每个公网请求先卡 IPv6 connect 约 120s，
sync 进程静默空转 2.5 小时零产出。根因与方案见
`docs/superpowers/specs/2026-09-22-ipv6-egress-guard.md`。

防护分三级，**前两级已内置在代码里，换机无需任何操作即生效**：

### 第 1 级：代码默认强制 IPv4（自动生效，无需操作）

`common/public_data/ipv4_egress.py` 的 `force_ipv4()` 在 `live-sync` 与
`gateway run` 启动时自动执行：进程内 `getaddrinfo` 过滤掉 AAAA 结果，
公网请求永远直连 IPv4。**只要部署的是本仓库代码，新机天然免疫。**

开关：`PUBLIC_DATA_ALLOW_IPV6=1` 可关闭（仅在未来 VPC 开通 IPv6 出网后使用）。

### 第 2 级：启动门禁 fail-fast（自动生效，无需操作）

若有人显式设置了 `PUBLIC_DATA_ALLOW_IPV6=1`，`live_safety` 门禁会在启动时
探测真实环境：「AAAA 优先 + IPv6 不通」→ 5 秒内拒绝启动并报
`ipv6_egress_stall`，绝不静默空转。

### 第 3 级：系统层双保险（可选，一条命令）

如希望系统层也优先 IPv4（保护本仓库以外的进程，如临时脚本、yum/pip 直连），
可加一行 gai.conf（幂等、可逆）：

```bash
grep -q "^precedence ::ffff:0:0/96  100" /etc/gai.conf || \
  echo "precedence ::ffff:0:0/96  100" >> /etc/gai.conf
```

> 注意：第 3 级是**可选加固**而非必需——2026-09-22 的裁决是不依赖它
> （机器配置会随机漂移，代码基线不会）。加了无害，撤了也无害。

### 验收（新机打完勾前必跑）

```bash
# 在 /opt/dops/repo 部署完成后，用应用 venv 验证公网解析直连 IPv4：
/opt/dops/venv/bin/python -c "
import time, urllib.request
t = time.time()
urllib.request.urlopen('https://api.dingtalk.com/v1.0/oauth2/accessToken', timeout=15)
print(round(time.time() - t, 2), 's')"
# 预期 < 2s（含 TLS）；若 ~120s → 代码基线未生效，检查部署版本
```

## §2. 换机/扩容流程（按序）

1. **L0-L1**：按首装实录 P0-P2（免密、hostname/hosts/时区、Docker）。
2. **L2 IPv6**：无需操作（代码基线自带）；可选执行 §1 第 3 级一条命令。
3. **L3**：按首装实录 P3 验证数据层。
4. **L4**：`/opt/dops` 布局 + app.env（600），scp 代码与 venv。
5. **总验收**：§1 验收命令 + `live-sync --source dingtalk` 冒烟一轮，
   `mart_ops.sync_runs` 到 `completed`。

## §3. 常见坑（IPv6 相关）

| 现象 | 判据 | 处置 |
|---|---|---|
| sync/gateway 启动即拒，报 `ipv6_egress_stall` | 有人设了 `PUBLIC_DATA_ALLOW_IPV6=1` 且机器无 IPv6 出网 | 去掉该环境变量（回到 IPv4 基线）；除非 VPC 已开通 IPv6 出网 |
| 公网请求偶发 ~120s 慢 | 代码基线未生效（部署了旧代码或第三方脚本绕过） | 确认部署版本含 `common/public_data/ipv4_egress.py`；脚本类走 §1 第 3 级 |
| `getaddrinfo returns empty list` | 目标域名只有 AAAA 无 A 记录 | 该域名无法走 IPv4，属业务依赖问题，需单独评估 |
