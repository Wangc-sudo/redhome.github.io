# 阶段 4 切换运行手册（日报机器人 → 容器化链路）

> 面向运维。代码侧已全部就绪并测试（448 例）；本手册是切换窗口的执行清单。
> 每步都有**验收点**与**回退点**；任何一步验收失败 → 停下并回退，不带病前进。

## 0. 切换前状态（已完成）

- 新链路：`钉钉表 → sync-dingtalk → raw → extract-mart → mart_ops → robot/gateway/pages`
- 报数新链路：`Stream → dingtalk-gateway → mart_ops`（AI 表不回写）
- 旧链路（现网）：cron 直跑脚本，读写钉钉 AI 表。**切换窗口内旧链路保持可用，作为回退。**

## 1. 发布真实 region 配置到 Nacos（替换种子占位符）

种子里 robotCode / conversationId / tableUrl 是占位符；真实值只进 Nacos。

1. 在仓库外准备真值文件（与 `docker/integration/regions.seed.json` 同 schema）。
2. 启动 Nacos 并发布：

```bash
docker compose -f docker-compose.integration.yml --profile nacos up -d nacos
PUBLIC_DATA_NACOS_SERVER=localhost:8848 \
python -m common.gateway.cli publish-regions --source /仓库外/regions-prod.json
```

3. **验收点**：Nacos console（group=`REGIONS`）可见 `region-hangzhou.yaml`，字段为真值。
4. 回退：删除该 dataId 即回退到种子（占位）值。

## 2. 数据链路双跑对照（只读侧）

不动现网 cron。跑新链路并逐日对照：

```bash
# 同步 + 提取（本地验收环境为 _test 库；生产按实际 APP_ENV）
--profile live-sync-dingtalk run --rm sync-dingtalk
--profile live-sync-wdt      run --rm sync-wdt
--profile extract            run --rm extract-mart
```

**验收点**（连跑 2 轮）：
- `sync_runs.status='completed'`，无 `failed`/`projection_pending`；
- `dim_calendar`、`dim_robot_member`（与现网 `config.json` 的 org.archives 人数一致）、`fact_*` 行数与 `record_id_digest` 稳定；
- `mart_cli leaderboard`（dry 对照）产出的未填名单/榜单数字与现网机器人当日输出一致。

## 3. 真群报数对照（写侧，用测试群）

1. 把测试群的 `robotCode`/`openConversationId` 发布为 region 配置（同第 1 步），启动 gateway：

```bash
PUBLIC_DATA_LIVE_CREDENTIALS_PATH=/仓库外/source-credentials.json \
docker compose -f docker-compose.integration.yml --profile dingtalk-gateway run --rm dingtalk-gateway
```

2. 在测试群 `@提醒事项 12800`。
3. **验收点**：
   - 群内收到 ✅ 回执（金额、累计、完成率与手算一致）；
   - `fact_daily_report_offline` 出现 `stream:hangzhou:<uid>:<date>` 行（或当日行被更新）；
   - 再报一次不同金额 → 🔁 覆盖提示出现；
   - 非责任人发言 → ⛔ 拒绝回执。
4. 回退：停 gateway 容器即可，现网 listener 不受影响。

## 4. cron 切换（robot / pages 上线）

1. 先启新：`robot-hangzhou`（profile `robot`，cron `0 18,20 * * *`）、`pages-hangzhou`（profile `pages`，cron `30 8 * * *`）、`dingtalk-gateway`（长驻）。
2. 观察 **2 个工作日**：18:30 提醒、20:00 催办+DING、8:30 榜单与现网输出一致（文案、@人、顺序）。
3. **验收点**：`robot_outbox` 每日出现 `remind`/`check`/`ding`/`leaderboard` 行且 `status='delivered'`；无 `failed`（达重试上限的行进控制面告警清单）。
4. 再停旧：注释现网 5 个 cron 项（保留不删，进入回退窗口，建议 1 周）。
5. **回退点**：回退窗口内恢复旧 cron、停新容器即可回到旧链路。

## 5. 旧路径退役（回退窗口结束后执行）

按序执行，每步单独可验证：

1. **关闭日报 AI 表同步**：从 `docker/integration/source-manifest.json` 的 `dingtalk.bases` 移除 `daily_report_offline` 与 `channel_daily_sales` 数据集（`dingtalk.org` 保留）。重跑 sync+extract 验证其余数据集正常。
   - ⚠️ 前置：第 3 步已确认报数全部走 Stream，且月目标已不再维护在 AI 表（目标的迁移方案另行确认——当前目标列仍由表同步提供）。
2. **删除 `recalc_totals`**：`core.recalc_totals`（重算+写回）与两个机器人的 `recalc_totals.py` 及对应 cron——达成率已改为共享口径派生（spec §10）。
3. **删除 `stateFile` 机制**：旧 `hangzhou_reminder.py` / `shaoxing_reminder.py` 的当日去重已由 `robot_outbox.dedupe_key` 接管。
4. **退役 `org_sync` 快照胶水**：`org_input_*.json` 快照流程停用；组织真源为 `dim_robot_member`（`sync-dingtalk` 按 `org.seed.json` 维护），机器人的 `members` 映射改读它。
5. **删除旧入口脚本**：`hangzhou_reminder.py`、`shaoxing_reminder.py`、两个 `leaderboard_report.py`、`hangzhou_listener.py`、`shaoxing_listener.py`（随对应容器验证完毕逐个删）。

## 6. 切换后常态

- 关停/扩线：Nacos `PIPELINES` 组改 `enabled`（robot/gateway/pages 各 service_id）；新增区域 = `regions.seed.json` + `pipelines.seed.yaml` + Nacos 发布 + 复制容器服务。
- 日历跨年：HR 更新 `docker/integration/calendar.seed.json` 的 `months`（国务院安排公布后），`extract-mart` 重跑即生效。
- 排班校验源（钉钉考勤）：按 spec §10 决策放 apps 层校验步骤，需要时另开任务。
