# 渠道管线迁 WDT：映射表与面板设计（2026-10-23）

第 1 步（`fact_order_line.buyer_nick`，PR #223）与第 2 步（`dim_channel_map`）已落地。
本文是**第 3 步（渠道日销聚合）**的设计与已知缺口，供下一轮直接开工。

## 一、映射表 `dim_channel_map`

- 迁移版本：`mart-ops-channel-map-v1`（mart 库），表 `dim_channel_map` +
  审计表 `dim_channel_map_audit`。
- 匹配三要素：`match_type`（shop / buyer_nick）+ `match_mode`（exact / prefix）+
  `match_value`（归一化后存储）。唯一键 `(match_type, match_value)`。
- `panel` 决定渠道归属哪个面板：`channel`（现有七大渠道）/ `channel_b2b`
  （B2B 客户新面板，2026-10-23 裁决「单独设计一个面板」）。
- 解析入口：`common/public_data/channel_map.py` 的 `resolve_channel(row, rules)`，
  规则按 `priority` 升序取首个命中；表未迁移时 `fetch_channel_map` fail-soft 返回空。

### 归一化（必须）

云上实锤同一主体混用全角/半角括号：

- `浙江天猫网络科技有限公司（寄售）`（全角）
- `浙江天猫网络科技有限公司(经销）`（左半角右全角）

`normalize_match_value` 统一去空白 + 全角括号转半角 + 小写后再比对。

## 三、裁决落地（2026-10-23）

1. **拼多多 / 抖音按店铺名映射区分**——此前判断「无法区分」是错的。云上 probe
   实锤 `shop_name` 自带平台前缀：`习水村-抖音习酒窖藏1988酒类旗舰店`、
   `杭易-拼多多致中和酒类旗舰店`、`习水村-视频号…`、`习水村-快手…`、
   `杭易-京东购喝旗舰店sop`。故新增 `match_type=shop` + `match_mode=contains`
   的平台规则：抖音/视频号→直播（AI 表「直播」= 抖音+视频号）、拼多多→拼多多、
   京东→京东、快手/得物/微盟→其它。`UNMAPPED_CHANNELS` 已清空。
2. **猫超 = 寄售 + 经销**（运维拍板）：两个抬头同指 `channel_key=猫超`。
3. **业务线四档**（新增 `business_line` 列，迁移 `mart-ops-channel-map-v2`）：
   线上渠道 `online` / 线下网点 `offline_store` / 餐饮 `dining` /
   体验馆与团购 `experience_group`。区域侧对齐常量 `REGION_BUSINESS_LINE`：
   vanke=体验馆与团购（万科体验馆 + 莲荷里体验馆 + 企业团购专属）、dining=餐饮、
   hangzhou/shaoxing/offline_all=线下网点、qudao=线上渠道。

## 四、面板设计（第 3 步产出面）

- 现有面板 `channel`：七大渠道日销 + 达成率（对齐 `CHANNEL_ORDER`）。
- 新面板 `channel_b2b`：丰享 / 海澜之家 / 酱云汇 / 其它，按客户抬头出日销与月累计，
  不参与七大渠道的月目标达成率（AI 表无对应目标，除非运维补登）。
- `business_line` 与 `panel` 正交：panel 决定「放哪块面板」，business_line 决定
  「算哪条业务线」，供第 3 步聚合按业务线出汇总。
