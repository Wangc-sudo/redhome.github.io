# 线下整体销售数据自动汇总方案

## 1. 背景与目标

目前线下有 3 个日报相关钉钉群：

| 群 | 角色 | 现状 |
|---|---|---|
| 杭州日报群 | 区域报数群 | 机器人报数已落库 |
| 绍兴日报群 | 区域报数群 | 机器人报数已落库 |
| 线下整体销售日报周报群 | 线下事业部汇总群 | 区域种子已预留（`offline_all`），尚无自动汇总 |

**目标**：把杭州、绍兴群里的报数自动汇总，合并**省外**和**李树军**的数据，形成一张「线下整体销售数据表」，并提供**日 / 周 / 月的环比**，按日自动推送到「线下整体销售日报周报群」。

## 2. 现状盘点（可复用能力）

- **报数落库**：各区域群成员 `@机器人 金额` 报数，经 `common/gateway/report_intake.py` 直写 MySQL `mart_ops.fact_daily_report_offline`，业务键 `(region, 表内用名, business_date)`，重复报数自动覆盖更新。
- **区域配置**：`docker/integration/regions.seed.json` 已定义 `hangzhou`、`shaoxing`、`offline_all`（备注即"线下事业部汇总群"）等区域，群 ID / robotCode 由 Nacos 下发，新增汇总口径只需配置，无需改代码。
- **统一口径**：`common/metrics/daily_report.py` 是达成率计算单点（月目标绝不可 SUM、已过工作日口径），汇总任务必须复用，避免口径分叉。
- **定时调度**：`common/public_data/scheduler.py` 长驻容器 cron + MySQL named lock 防重入；`common/daily_robot/mart_cli.py`（remind/check/once）+ `robot_outbox` 幂等投递（唯一键 `region:kind:business_date`）已是成熟模式，每日汇总任务照此实现即可。
- **环比参考**：渠道日报 `common/daily_robot/channel_daily.py` 已有环比 + 金额格式化的表格样式，可逐字对齐。
- **缺口**：目前没有任何"线下整体日/周/月报自动汇总"任务，本方案即补此增量。

## 3. 总体设计

```
杭州日报群 ─┐
绍兴日报群 ─┼─> fact_daily_report_offline（已落库）
省外 ───────┤        │
李树军 ─────┘        ▼
        【汇总任务 daily/weekly/monthly】（新增，口径复用 metrics）
                     │
                     ▼
        线下整体销售数据表（mart 汇总表 + BI 看板）
                     │
                     ▼
        robot_outbox → 网关投递 → 线下整体销售日报周报群
```

### 3.1 数据来源与缺口补齐

杭州、绍兴数据已在库内，关键缺口是**省外**和**李树军**的数据入口。三个选项（可组合）：

1. **推荐：给省外单开一个报数区域**（如 `region=shengwai`，可让李树军挂在该区域下或单列成员）。复用现有报数落库全链路，零新代码，只需 Nacos 加一份 `region-shengwai.yaml` 并把机器人拉进群。数据质量、催办、补签能力全部白得。
2. 若省外暂不建群：由管理员在任一群用 `/补签 姓名 [日期] 金额` 代录（现有能力，追溯 30 天），省外/李树军以"虚拟成员"身份挂到 `offline_all` 区域的在册成员表 `dim_robot_member`。
3. 过渡兜底：钉钉 AI 表批量导入 → 现有 raw/mart 管道同步进事实表。

**结论**：方案按选项 1 设计，选项 2 作为过渡，选项 3 兜底。

### 3.2 汇总数据表（mart 层）

新增汇总表 `mart_ops.agg_offline_daily`（每日跑批生成/覆盖）：

| 字段 | 说明 |
|---|---|
| stat_date | 统计日期 |
| scope | `hangzhou` / `shaoxing` / `shengwai` / `lishujun` / `offline_total` |
| sales_amount | 当日销售额合计 |
| dod_amount / dod_rate | 日环比（对昨日） |
| wow_amount / wow_rate | 周环比（对上周同日） |
| mom_amount / mom_rate | 月环比（当日累计 对 上月同期累计） |
| month_completed / month_target / month_rate | 本月累计 / 月目标 / 达成率（复用 metrics 口径） |

口径要点：
- 日环比 = 当日 ÷ 前一自然日；**周环比 = 当日 ÷ 上周同星期几**（避开周末错位）；月环比 = 本月 1 日至当日累计 ÷ 上月 1 日至同日日累计。
- 月目标沿用"MAX 不 SUM"规则；省外/李树军若无目标值则达成率留空，只参与金额汇总。
- `offline_total = hangzhou + shaoxing + shengwai(+李树军)`，由区域配置驱动，未来加区域（如万科并入口径变化）只改配置。

### 3.3 推送任务（新增）

照 `mart_tasks.py` 同款实现三个任务：

| 任务 | 触发 | 内容 |
|---|---|---|
| `offline_daily_summary` | 每日 20:30（催办收口后） | 当日各板块金额 + 总计 + 日环比/周环比 + 本月累计达成，Markdown 表格发群 |
| `offline_weekly_summary` | 每周一 09:30 | 上周周报：周合计、周环比、各板块排名 |
| `offline_monthly_summary` | 每月 1 日 10:00 | 上月月报：月合计、月环比、达成率榜单 |

消息写 `robot_outbox`（kind=`daily_summary` 等，幂等键自带，重跑不重复发），由 `dingtalk-gateway` 投递到 `offline_all` 群。表格样式对齐渠道日报环比表。

### 3.4 BI 看板

`agg_offline_daily` 挂到现有 `common/bi_web`，提供按日期范围 / 板块筛选的查询页，替代人工拼表。

## 4. 实施计划

| 阶段 | 内容 | 依赖 |
|---|---|---|
| P0 数据补齐 | 决策省外/李树军入口（建群 or 代录）；Nacos 配置 `region-shengwai` 或 `dim_robot_member` 虚拟成员 | 运维拉群/配置 |
| P1 汇总落表 | 新建 `agg_offline_daily` schema + 每日汇总管道（挂 scheduler 注册表，named lock 防重入） | P0 |
| P2 日报推送 | `offline_daily_summary` 任务 + outbox 投递到汇总群，表格含日/周环比 | P1 |
| P3 周报月报 | 周/月汇总任务 + 月环比 | P2 |
| P4 看板 | bi_web 查询页 | P1 |

## 5. 风险与说明

- **省外数据及时性**：若走代录模式，汇总完整性依赖管理员录入；建群报数可根治。
- **口径一致性**：汇总任务禁止自写达成率 SQL，必须调 `common/metrics/daily_report.py`，否则与 `/我的`、`/门店` 指令口径打架。
- **历史数据**：任务上线后从上线日起跑；如需回补历史，用管道水位补跑，不回填 outbox 消息（避免群里刷屏）。
- **卡片菜单**：PoC 结论（公共模板按钮无回调）不影响本方案；汇总推送用普通 Markdown 消息即可。
