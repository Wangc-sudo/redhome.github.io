## 二、关键发现：`settings.py` 不用改

这大幅缩小了改造范围。

```python
# common/public_data/settings.py:89-98
database_names["manual"] = (
    "raw_manual_test" if app_env == "test" else "raw_manual"
)
for database_name in database_names.values():
    is_test_database = database_name.endswith("_test")
    if app_env == "test" and not is_test_database:
        raise ValueError("APP_ENV=test requires database names ending in '_test'")
    if app_env == "production" and is_test_database:
        raise ValueError("APP_ENV=production rejects database names ending in '_test'")
```

`settings.py` 只约束「production 不得用 `_test` 后缀」，**正式名天然满足**；
manual 库还会自动推导为 `raw_manual`，无需额外配 `PUBLIC_DATA_MANUAL_DATABASE`。

> ✅ 结论：**唯一必须改的代码是 `live_safety.py`**。
> `settings.py` 只需补一次验证（T2），不需要修改。

## 五、备注：为什么提示词要写"不要改 settings.py"

如果 AI 没被告知这一点，很可能会顺手把 `settings.py:93-98` 的 `_test` 互斥规则也「改造」掉——
那是画蛇添足，还会破坏「test 环境强制 `_test` 后缀」这条对新增库同样生效的铁律
（`settings.py:83-84` 注释明写）。写死"不要改"能避免误伤。
