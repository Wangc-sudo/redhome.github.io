# CI/CD 全量迁云方案（2026-09-28）

> 背景：本地环境（e:/repos 那台千问办公机）废弃，源码唯一事实源 = GitHub
> 仓库（`Wangc-sudo/redhome.github.io`）。**本机已无 Docker**——集成测试
> （`docker-compose.integration.yml`，448 例）本机跑不了，只在 GitHub Actions
> 的 runner 上跑；本机仅剩纯 `python -m unittest` 单测可用。本文定 CI/CD 怎么写、怎么落地。

## 一、架构：CI 在 GitHub 做质量门，CD 用拉模式 GitOps

```
开发者 push / PR
   │
   ▼
GitHub Actions（CI，只读质量门）
   python-lint  +  python-tests(448 集成)  +  frontend(build)  →  gate
   │  全绿才允许合并 main（branch protection 只要求 gate 一个 check）
   ▼
合并 main ＝部署意图
   │
   ▼   （每 2 分钟，各主机自拉；出向 443，零 SG 改动）
dops-app(.3) / dops-ci(.5)  systemd timer → ops/deploy.sh 快照
   git fetch → 有变更则 compose up -d（按需重建镜像）→ 健康门 → 失败自动回滚
```

### 为什么是拉模式，不是 push 式 SSH / 自托管 runner

| 约束（实测） | 推论 |
|---|---|
| SG 拦 inbound 22，仅办公网 IP 白名单 | GitHub-hosted runner 无固定 IP，加不了白 → push 不到 |
| **VPC 内 22 也不通**（`.195→.3:22` 超时） | 自托管 runner 放 dops-ci 也 SSH 不到 dops-app |
| 出向 443 到 GitHub 放开 | 各主机能自己 `git pull` ✅ |

拉模式零安全组改动、三机同一套逻辑、dops-ci 顶替灾备天然成立。
（铁律「SG 只加不删」下也能走，但拉模式连这条都不用碰。）

## 二、本次新增/更新的文件

| 文件 | 作用 |
|---|---|
| `.github/workflows/ci.yml` | 质量门：lint + 集成测试 + 前端 + `gate` 汇总；加 concurrency / workflow_dispatch；删掉「定时任务仍在本机」的过时注释 |
| `docker/cloud/Dockerfile` | **补缺**：dops-app 生产运行时镜像的版本化构建（此前服务器手工构建、无 Dockerfile）。只装 python3+requirements，代码靠 bind-mount |
| `ops/deploy.sh` | CD 核心：拉取→(依赖变则重建镜像)→`compose up -d`→健康门→失败回滚；flock 防并发；写日志+`deploy-status.json` |
| `ops/dops-deploy.service` / `.timer` | systemd 拉取循环（每 2min）；service 跑**快照副本**（`git reset --hard` 不会改写到正在执行的脚本） |

边界保持不变：`/opt/dops/app.env`、`/opt/dops/live/**` 机密在宿主机、**不入库**、CD 不触碰。

## 三、一次性落地步骤（每台 dops 主机）

> ⚠️ **顺序铁律**：先把「要上线的代码」合并并 push 到 `main`，再开 timer。
> 否则第一次 `git reset --hard origin/main` 会把服务器上**未入库的改动全部冲掉**
> （包括 09-28 我 scp 上去的 queries.py P0 修复——它还没 commit）。
> 当前本地 `chore/p1-sync` 领先 origin 21 个提交 + 大量未提交改动，需先收口。

```bash
# 0) 本地：收口并推送（按仓库惯例，push 需单独确认）
#    合并意图代码到 main 并 push origin main

# 1) 服务器：把 /opt/dops/repo 转成 git 工作副本（保留 app.env/live，它们在 repo 外）
cd /opt/dops/repo
git init
git remote add origin https://<只读PAT>@github.com/Wangc-sudo/redhome.github.io.git
git fetch origin main
git reset --hard origin/main          # 内容应与现状一致（前提：已 push）
git branch -M main && git branch --set-upstream-to=origin/main main

# 2) 装 timer
cp /opt/dops/repo/ops/dops-deploy.service /etc/systemd/system/
cp /opt/dops/repo/ops/dops-deploy.timer   /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now dops-deploy.timer

# 3) 验证：手动跑一次应为 no-op（HEAD==origin/main）
systemctl start dops-deploy.service
journalctl -u dops-deploy.service -n 20 --no-pager
cat /opt/dops/deploy-status.json
```

dops-ci(.5) 同样步骤（它是灾备 + 可顶替 dops-app）。dops-ctrl(.4) 只跑 Nacos，不需要。

## 四、回滚

- **自动**：deploy.sh 健康门失败 → 自动 `reset --hard` 回部署前 SHA 并重建。
- **手动**：`cd /opt/dops/repo && git reset --hard <上个好SHA> && systemctl start dops-deploy.service`（或直接 `compose up -d --force-recreate`）。
- 查部署历史：`tail /opt/dops/logs/deploy.log`、`cat /opt/dops/deploy-status.json`。

## 五、要你拍板的决策

1. **部署分支**：默认 `main`（合并即部署）。若要先灰度，改 `DOPS_DEPLOY_BRANCH=release`（写进 `/opt/dops/deploy.env`），main→release 手动挑。
2. **轮询间隔**：默认 2min。要快可 1min；要省可 5min。改 `dops-deploy.timer` 的 `OnUnitActiveSec`。
3. **Git 认证**：服务器拉私有库要只读凭证——建议 GitHub **Deploy Key（只读）** 或只读 PAT 放 `/opt/dops/.git-credentials`，别用个人账号密码。
4. **requirements 变更**：默认在**本机重建镜像**（dops-app 只装依赖，构建快）。若嫌占生产机，转 Phase 2。

## 六、Phase 2（成熟态，可选）

- **镜像即产物**：dops-ci 上加 GitHub 自托管 runner，CI 里 `docker build` dops-app → 推天翼云 **CRS 镜像仓库**；compose 不再 bind-mount 代码、改为 `:tag` 镜像；服务器 `docker pull + up -d`。回滚=换 tag，最干净。
- **部署回执**：deploy.sh 末尾回调 GitHub Deployments API，在 PR/Actions 页看到「已部署到 dops-app」。
- **前端产物**：frontend 7500+ 文件，构建放 dops-ci 自托管 runner，dist 进镜像或对象存储。

> Phase 1（本方案）不动 SG、不动镜像模型、今天就能跑；Phase 2 等 bind-mount→镜像 重构排期后平滑切换。
