# digital-ops 测试环境配置单（开环境用）

> 目标：一套独立测试环境，跑通 `sync → extract → robot/pages → gateway` 全链路。
> 架构原则：**纯出站、零入站**。不需要公网 IP、不需要开放任何入站端口。

## 1. 服务器

| 项 | 要求 | 说明 |
|---|---|---|
| 数量 | 1 台即可（全套 compose 单机部署） | 生产可再拆 |
| OS | Linux x86_64（Ubuntu 22.04+/Debian 12+ 均可） | 时区必须 **Asia/Shanghai**（CURDATE() 驱动月份窗口） |
| Docker | Docker 24+ 且带 compose 插件 | `docker compose version` 可用 |
| 规格 | 建议 2C / 4G / 40G 盘（最小 2C/2G/20G） | MySQL 8.4 + Nacos + 若干一次性 Python 容器 |
| 代码 | `git clone` digital-ops 仓库到服务器 | 所有镜像由仓库 `docker/integration/Dockerfile` 本地构建 |

## 2. 网络（只配出站白名单，无入站）

| 方向 | 目标 | 端口 | 用途 |
|---|---|---|---|
| 出站 | `api.dingtalk.com` | 443 | 钉钉 OpenAPI（取 token / 读智能表 / 发群消息） |
| 出站 | `oapi.dingtalk.com` | 443 | 钉钉通讯录接口（组织同步） |
| 出站 | `wss-open-connection-union.dingtalk.com` | 443 (WSS) | Stream 长连接收群消息（由 gateway 主动外连，**非回调**） |
| 出站 | `wdt.wangdian.cn` | **80 (HTTP)** | 旺店通 OpenAPI |
| 出站 | `cdn.jsdelivr.net` | 443 | 仅浏览器端加载 ECharts（BI 看板页面）；服务器本身不需要 |
| 入站 | 无 | — | MySQL 13306 / BI 18080 / Nacos 8848 全部只绑 `127.0.0.1` |

## 3. 钉钉侧资源（需钉钉管理员协助开通）

| 资源 | 说明 |
|---|---|
| 企业内部应用 ×1 | 产出 `app_key` / `app_secret`；需开权限：通讯录部门/成员读取、智能表格（notable）读写、机器人 `robot/groupMessages/send`、**Stream 模式**（应用内开启） |
| 群机器人 robotCode | 上述应用的机器人 `robotCode`（发群消息用） |
| 测试群 ×2 | 一个模拟「杭州日报群」、一个模拟「万科日报群」；各取 `openConversationId`（机器人入群后由 Stream/接口获取） |
| `operator_id` | 智能表操作人 userId（sync 写表头/读表用） |

## 4. 旺店通侧资源

| 资源 | 说明 |
|---|---|
| `sid` / `app_key` / `app_secret` | 旺店通 OpenAPI 账号（同步 `sync-wdt` 用；不开 WDT 则可暂缓该线） |

## 5. 仓库外机密文件（不入 git，手工放置）

| 文件 | 位置（建议） | 内容模板 |
|---|---|---|
| `source-credentials.json` | 服务器仓库外目录 | 见仓库 `docker/integration/live-source-credentials.example.json`：`dingtalk.{app_key,app_secret,operator_id}` + `wdt.{sid,app_key,app_secret}` |
| `regions-prod.json` | 服务器仓库外目录 | 与 `docker/integration/regions.seed.json` 同 schema，填入真实 `robotCode`/`openConversationId`/`tableUrl`/`leaderboardUrl`，vanke 区加 `monthlyTargets`（表内用名→金额） |

## 6. 环境变量（启动 compose 前 export 或写入 .env）

| 变量 | 必填 | 说明 |
|---|---|---|
| `PUBLIC_DATA_LIVE_MANIFEST_PATH` | 是 | 指向仓库内 `docker/integration/source-manifest.json` 的绝对路径 |
| `PUBLIC_DATA_LIVE_CREDENTIALS_PATH` | 是 | 指向第 5 节 `source-credentials.json` 绝对路径 |
| `BI_WEB_TOKEN` | 是（用 BI 时） | BI 看板访问令牌，自定义强随机串 |
| `PUBLIC_DATA_NACOS_SERVER` | 否 | 不启 Nacos 时留空，自动回退种子文件 |
| `PUBLIC_DATA_REDIS_URL` | 否 | 设 `redis://redis:6379/0` 才启用 Redis 缓存（可选增强） |
| `PAGES_OUTPUT_DIR` | 否 | 榜单 HTML 输出目录，默认 `./docker/integration/pages-output` |

## 7. 数据库（compose 自带，无需单独采购）

- MySQL 8.4 容器，首启自动执行 `mysql-init/001-create-test-databases.sql`：
- 库：`raw_dingtalk_test` / `raw_wdt_test` / `mart_ops_test`（utf8mb4）
- 账号：`public_data_test` / `public-data-test-password`（测试环境口令，生产另设）
- root：`local-integration-root`；数据卷 `public-data-mysql-data`

## 8. 服务清单与启动矩阵

| 服务 | profile | 形态 | 定时建议（cron） | 持凭据 |
|---|---|---|---|---|
| `mysql` | 默认 | 长驻 | — | 否 |
| `nacos` | `nacos` | 长驻（可选） | — | 否 |
| `sync-dingtalk` | `live-sync-dingtalk` | 一次性 | `0 2 * * *` | 是（钉钉） |
| `sync-wdt` | `live-sync-wdt` | 一次性 | `0 2 * * *` | 是（WDT） |
| `extract-mart` | `extract` | 一次性 | `0 4 * * *` | 否 |
| `robot-hangzhou` / `robot-vanke` | `robot` | 一次性 | `0 18,20 * * *` | 否 |
| `pages-hangzhou` / `pages-vanke` | `pages` | 一次性 | `30 8 * * *` | 否 |
| `dingtalk-gateway` | `dingtalk-gateway` | **长驻** | — | 是（钉钉） |
| `bi-web` | `bi-web` | 长驻 | — | 否 |
| `redis` | `bi-web-redis` | 长驻（可选） | — | 否 |

## 9. 开通后验收（由我执行或照此自查）

1. `sync-dingtalk` 跑通：`sync_runs.status='completed'`，`mart_ops_test.dim_robot_member` 有人数且 `dept_name` 非空；
2. `extract-mart` 跑通：`fact_*` 有行、`dim_calendar` 覆盖当月；
3. `dingtalk-gateway` 启动后日志出现 Stream `open connection`（无需任何入站配置）；
4. 测试群发一条报数 → 群内收到回执、`fact_daily_report_offline` 落行；
5. `robot-vanke leaderboard` 产出 outbox 行且 gateway 投递后 `status='delivered'`；
6. `http://127.0.0.1:18080` 带 token 打开 BI 看板。

## 10. 安全边界（与现网约定一致）

- 机密只存在于仓库外文件与 Nacos，不进 git 历史；
- 所有业务端口仅回环；钉钉交互全部出站（HTTPS + WSS），无 webhook 回调；
- 写库命令均有 `--confirm-local-test-write` 安全门，误连生产库会被拒绝。
