## 3. 数据模型

新表均通过统一迁移入口创建，不允许运行时绕过迁移临时建表。

- `pd_dataset_freshness`：业务数据集当前新鲜度、采集/加工/发布时间、滞后、差异、检查详情。
- `pd_knowledge_index_freshness`：知识索引源版本、内容指纹、模型、维度、索引版本、源/索引/待处理/失败数量。
- `pd_ops_run_history`：服务运行历史及完成状态，供对账、SLA 和运行面板使用。
- `pd_ops_dead_letter`：连续/永久/未知结果失败的死信状态，人工成功后解除。
- `rag_index_state`：商品条目指纹、模型、真实维度、本轮可见性、成功时间、degraded/attempts。
- `kb_qa_query_snapshot`：按请求人与会话冻结的可导出结构化结果，禁止二次执行 SQL。
- `kb_qa_export`：随机任务 ID、文件元数据、状态机、过期时间、下载/发送审计。
- 数据质量 V1/V2 表：规则覆盖、重放运行和规则/覆盖快照。

对应迁移版本：

- `mart-ops-data-quality-v1`、`mart-ops-data-quality-v2`
- `mart-ops-run-history-v1`
- `mart-ops-dead-letter-v1`
- `mart-ops-freshness-v1`
- `mart-ops-rag-index-state-v1`
- `mart-ops-kb-query-snapshot-v1`
- `mart-ops-kb-export-v1`、`mart-ops-kb-export-v2`（补 `started_at` 运行租约列）
- `mart-ops-kb-qa-audit-v4`

## 4. 配置与开关

生产配置放在服务器本地 `app.env`，不得写入 Git。

```ini
# XLSX 总开关与群通道独立开关；默认关闭
KB_EXPORT_ENABLE=0
KB_EXPORT_GROUP_ENABLE=0
KB_EXPORT_DIR=/opt/dops/kb-exports
KB_EXPORT_MAX_ROWS=50000
KB_EXPORT_TTL_HOURS=24
KB_EXPORT_MAX_FILE_MB=20

# 自动恢复默认关闭
AUTO_RETRY_ENABLE=0
AUTO_RETRY_MAX_ATTEMPTS=3
AUTO_RETRY_BACKOFF_SECONDS=60
AUTO_CATCHUP_ENABLE=0
AUTO_CATCHUP_MAX_AGE_SECONDS=3600
AUTO_REPLAY_ENABLE=0

# 索引自动删除默认关闭
INDEX_AUTO_DELETE_ENABLE=0
INDEX_DELETE_MAX_COUNT=100
INDEX_DELETE_MAX_RATIO=0.1

# 嵌入资源参数；Milvus Lite 保持单写者
RAG_EMBED_TEXT_BATCH=16
RAG_EMBED_IMAGE_BATCH=8
RAG_EMBED_CONCURRENCY=1
```

说明：

- Web 导出由 `KB_EXPORT_ENABLE` 控制；群导出还须显式打开 `KB_EXPORT_GROUP_ENABLE`。
- `kb-gateway`、`scheduler`、`bi-web` 使用同一个 `KB_EXPORT_DIR`，避免生成/下载/清理路径不一致。
- `kb-export-cleanup` 每小时运行，只清理过期导出，不碰业务数据。总导出开关关闭时清理仍可执行。
- `dataset-freshness-check` 通过现有管道注册与启停控制。
- 自动重试、重放、补跑和索引自动删除均保持独立开关，不能由前端按钮绕过。

## 6. 安全与恢复语义

- 导出只读冻结快照；同一快照重复导出不重查数据库，不消耗 LLM token。
- 创建、生成、下载和群发送均重新校验请求人、会话和权限；文件以随机名落盘，下载只走授权 API。
- Web 任务状态持久化，启动时原子认领 pending 或租约过期的 running 并恢复；过期任务统一下载拒绝并清文件。
- 商品向量先写 staging ID，默认检索排除 staging；核对数量、维度和抽样检索后才以原生 upsert 发布生产 ID，生产侧再次抽样，失败回滚本轮 last-good。
- 文档与商品索引共用 MySQL 命名锁；调度器限制 CPU/内存/进程数，嵌入批量可配且并发固定为 1。
- 知识索引 API 与调度检查均按当前时间重判 SLA，索引停止后不会让最后一条 fresh 永久残留。
- 文档按内容版本发布，新版完整可检索后才清旧版。
- 自动删除只接受条目标识列表；源为空、源不完整或本轮失败时不删除。
- 自动重放仅允许明确未启动的运行；结果未知、已启动、已投递或超出限制进入死信。
- 后台死信恢复复用受审计的 run-once，不在页面拼接任意命令。

## 7. 生产发布顺序（已按此顺序执行）

1. 核对云上 `/opt/dops/repo` 分支、HEAD 和工作区，备份 `app.env` 与 `docker-compose.dops.yml`。
2. 创建宿主机目录 `/opt/dops/kb-exports`，配置第 4 节环境变量，先保持所有新开关关闭。
3. 校验 Compose：

   ```bash
   docker compose -f /opt/dops/repo/docker/cloud/docker-compose.dops.yml config --quiet
   ```

4. 先执行统一 migrate，核对 `pd_live_schema_migration` 的版本、校验和与完成状态。
5. 发布新增管道并重建 `scheduler`、`kb-gateway`、`bi-web`、`ops-web`；`compose up -d` 显示 Started 不等于应用 env 变化，必要时 `--force-recreate`。
6. 重建 Milvus 检索并抽样验证文档和商品新版本；保持 `INDEX_AUTO_DELETE_ENABLE=0`，先检查删除计划。
7. 仅打开 Web 导出，用一个测试会话验证：普通查询、查询并导出、追问导出、重复导出、跨会话拒绝、过期清理。
8. 群导出仅在独立测试群启用，核对 `sampleFile` 的 errcode、文件可读性和 `sent_at`。
9. 自动恢复按重试、限量补跑、受限自动删除顺序灰度；每一步观察 run history、死信和上下游对账。

## 9. 回滚

- 导出：先关 `KB_EXPORT_GROUP_ENABLE` 和 `KB_EXPORT_ENABLE`，保留 `kb-export-cleanup` 清理存量文件；不回删业务表。
- 自动恢复：关闭 `AUTO_RETRY_ENABLE`、`AUTO_REPLAY_ENABLE`、`AUTO_CATCHUP_ENABLE`；已有死信保留审计。
- 索引删除：立即关闭 `INDEX_AUTO_DELETE_ENABLE`；保留 last-good，不回填未经核对的向量。
- 应用回滚：按备份恢复 Compose/env，代码回滚前确认新旧代码均兼容已新增表；禁止用 DROP TABLE 当回滚。
- 前端：恢复对应构建产物并强制刷新；API 回滚与前端回滚必须同批，避免调用不存在的导出端点。
