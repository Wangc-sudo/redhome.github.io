## 3. 目标口径

1. **格是唯一核算单位**：应报清单 = Σ(单元 × 该单元需报板块)；催办、未填、进度、榜单全部以格为粒度。
2. **部门推断**：单元 = 在册成员的 `dept_name`（经别名归一）；该单元的默认板块 = `零售、团购`；**`企业团购` 默认不开放**，只对显式声明它的单元开放（= A1 宣蕾凤专属）。
3. **名册兜底**：配置可强制指定某格/某单元的负责人，用于纠偏（一人代管两店、临时顶岗）；名册里写了但 `dim_robot_member` 查无此人的，记 warning 并退回部门推断。
4. **写入格式不变**：仍写 `responsible_person = "<单元>·<板块>"`（分隔为 U+00B7 中点）。→ **历史数据零迁移**，既有 4 格事实行无需任何处理；催办/榜单这些消费侧才是本次要改的地方。
## 4. 配置模型（Nacos `region-vanke.yaml`）

在 `RegionConfig` 新增两个可选字段（驼峰，与 `deptOrder`/`storeExclude` 一致）：

| 字段 | 类型 | 语义 |
|---|---|---|
| `reportUnits` | list[object] | 单元字典。`name`(规范名，= 通讯录部门名) / `aliases`(口语写法) / `metrics`(该单元需报板块，**缺省 = `["零售","团购"]`**) |
| `reportRoster` | map | 负责人兜底。key = `"<单元>·<板块>"`（精确格）或 `"<单元>"`（该单元全部板块），value = 实名列表 |

示例值（宣蕾凤部门已实测定位，09-29）：

```yaml
reportUnits:
  - name: 万科体验馆
    aliases: [万科]
  - name: 莲荷里体验馆
    aliases: [莲荷里, 大莲花, 酱酒体验馆, 酱香体验馆, 酱酒, 酱香]
  - name: 品牌部（线下）     # 宣蕾凤所在部门（dept_id=1049750665，实测）
    aliases: [企业团购, 品牌部]
    metrics: [企业团购]      # 该单元只报这一个板块——必须显式，否则 6 人都会按默认两格被催
reportRoster:
  "品牌部（线下）·企业团购": [宣蕾凤]   # 锁定负责人；不写则部门 6 人都会被 @
monthlyTargets:
  万科体验馆·零售: 0
  万科体验馆·团购: 0
  莲荷里体验馆·零售: 0
  莲荷里体验馆·团购: 0
  品牌部（线下）·企业团购: 0   # 运维补真值前保持 0（= 不显示完成率，不报错）
```

**向下兼容**：字段全部可选——区域不配 `reportUnits` 时行为与今天完全一致（回退内置门店别名表 + 零售/团购 两板块），因此 hangzhou / shaoxing / junpin 不受影响，改动可按区域灰度。

> 实施提醒（易漏）：`region_config._to_mapping()` 是 Nacos 覆盖的重建出口，**新增字段必须同步加进**它和 `_parse_region()`，否则下发后字段被静默丢弃。

### P1（本方案主体）

**P1-1 期望格计算（新增）** `common/metrics/daily_report.py`（或独立模块 `common/daily_robot/report_cells.py`）

```python
@dataclass(frozen=True)
class ReportCell:
    label: str          # "<单元>·<板块>"，= 写入 responsible_person
    unit: str
    metric: str
    owners: tuple       # dim_robot_member 行（可能空 = 无人负责，需告警）
```

`expected_cells(region_cfg, members)` 纯函数（可单测，不连库）：
1. 别名归一：`alias -> unit`（来源 = `reportUnits`，缺失则用模块内置 `_STORE_ALIASES`）；
2. 按归一后的 `dept_name` 分桶；**根部门（`dept_order[0]`）成员不占格**（他们只是跨店代报的管理者）；
3. 每单元的板块 = `reportUnits` 中该单元的 `metrics`，缺省 `("零售","团购")`；
4. 负责人 = `reportRoster` 命中优先，否则该单元全部成员；roster 中查无此人 → `logger.warning` + 退回部门推断。
5. 新设部门 / 新入职 / 调岗：只要成员部门归一后落在一个单元上，格就自动生成（或用 Rostering 纠偏），无需改代码——这是相对现状 B2 的主要收益。

`missing_cells(connection, region_cfg, business_date, members)` = `expected_cells` 减去当天 `fetch_filled_names` 命中的格。

**P1-2 定时播报改走格口径** `common/daily_robot/mart_tasks.py`
- `_unfilled()` 增加分支：`region_cfg` 为多板块（存在 member 部门命中任一 unit）→ 返回 `missing_cells`；否则维持现有 `unfilled_members` 人名口径 → **hangzhou/shaoxing 零影响**；
- `build_reminder_message` / `build_check_message` 增 `cells` 分支，正文形如：

```
### 📋 销售日报填写提醒（万科&大莲花&团购 9月30日 周三）

今日还有 3 个板块未填报：
- 万科体验馆·团购（张燕芳）

- <团购部>·企业团购（宣蕾凤）

在群里 @日报小机器人 报数即可，如「万科体验馆 团购 12000」
[点此填写](<tableUrl>)
```

- **@ 口径**：`at_user_ids` = 缺失格负责人的并集（去重，替换现在的"全员"）；DING 行同样只发这些人；

> 钉钉限制：**群 @ 是消息级**（消息体的 `atUserIds`），无法做逐行 @。因此采用"正文逐行列出 `板块（负责人）`、@ 由消息级命中这些负责人"的组合，这是现有 API 下可达的最细粒度，需评审确认。

1. P0-0 恢复组织同步 → 手动跑一次 `sync-dingtalk` → 定位宣蕾凤部门 id → P0-1（org.seed 纳编或组织调整）→ `sync-dingtalk` + `extract-mart` 重建 dim → P0-2 回填 `<团购部>` 与 `reportRoster`；

3. 部署代码（分支作业），重建 gateway + scheduler 容器（`docker compose up -d`，勿用 restart）；
4. **首个工作日双人值守**：核对 18:30 提醒、20:00 催办 @范围、5 人回执、 `/未填`、`vanke.html` 新增行；
