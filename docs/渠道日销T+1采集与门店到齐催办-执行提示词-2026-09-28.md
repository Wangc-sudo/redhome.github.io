## 0. 已拍板口径（不再讨论，直接实现）

1. **10:31 采集 T-1（昨天）数据**：`business_date = 今天 - 1 天`（北京时区）。
2. **缺失判定**：
   - T-1 该店无行 → **缺**（催）
   - `sales_amount IS NULL` → **缺**（催）
   - `sales_amount = 0` → **已填写，不催**，但必须**在群播报里列出**（"零销售"段，不 @）
   - 金额 > 0 → 到齐
3. **播报群**：`region = qudao`（渠道日报群，复用现有 `robot-qudao` 的 robotCode / openConversationId）。
4. **只做 10:31 一次催办**：不做 DING、不做 14:00 二次复核（观察两周后再议）。
5. **触发条件**：有缺口门店 **或** 有零销售门店 → 发一条；两者都无 → 静默（仅日志）。

## 2. P1：T+1 采集窗口（10:31）

### 2.1 `live-sync` 增加 `--dataset` 过滤

`common/public_data/cli.py`：
- `live_sync` parser 增加 `--dataset`（`action="append"`，可重复），支持**前缀通配**（如 `channel_daily_sales*`）。
- 透传给 `service.sync(manifest, source=..., datasets=...)`。

`common/public_data/live_sync.py`：
- `sync(manifest, source=None, datasets=None)`：`datasets` 为空时行为完全不变（向后兼容）；非空时只同步命中的数据集（前缀 `*` 通配），`run_id` 语义与失败独立性保持不变。
- 未命中任何数据集 → 明确报错退出（不要静默"成功"）。

### 2.2 `extract-mart` 增加同样的 `--dataset` 过滤

- 只投影 `channel_daily_sales` + `channel_monthly_target`（**月目标表必须带上**：点名册与店铺月目标链依赖 `fact_channel_store_target`）。
- 其余数据集行为不变。

### 2.3 登记三条新调度

## 3. P2：门店到齐校验 + @ 负责人（10:40）

### 3.1 新增 `common/daily_robot/channel_missing.py`

纯逻辑与 IO 分离（照 `extract_ecom_people.py` 风格），函数建议：

- `expected_stores(rows_target, rows_recent, *, exclude)`：点名册 = `fact_channel_store_target` 全店 **∪** 近 30 天 `fact_channel_daily_sales` 活跃 `store_name` **−** `storeExclude`；返回 `{store: channel}`。
- `store_states(rows_daily)`：T-1 每店的 `sales_amount` → `MISSING`（无行/NULL）/ `ZERO`（=0）/ `OK`（>0）。
- `channel_rollup(rows_daily, fallback_owners)`：店铺名为空的行（猫超式整渠道留空）按 `channel` 判，归属走 `channel_fallback_owners`。
- `owners_for(store, ...)`：明细行 `responsible_person` → `fact_channel_store_target.owners_json` → 渠道级兜底（**与 `build_fact_rows` 优先级完全一致**）。
- `resolve_at_user_ids(conn, owners)`：
  1. `unionId` → `dingtalk_org_member.payload_json.unionid` → `user_id`（**P0 实测字段是否存在，不存在则整级跳过并记 WARNING**）
  2. 姓名精确匹配 `dim_robot_member`（跨 region）；多个命中 → 视为歧义，**不 @**，进"无法@"名单
  3. 都无 → 文本点名
- `build_missing_message(*, display, business_date, missing_rows, zero_rows, unmatched_names, url)` → `(title, body_md)`：
  - 第一段「以下门店昨日未上报数据」表格（渠道｜门店｜负责人），末尾 @ 去重后的 userId
  - 第二段「以下门店昨日上报为 0」（**只列表，不 @**）
  - 无法映射的姓名单列一行"（张三 未匹配到钉钉账号，请手动提醒）"
  - 尾部 AI 表链接 + "已填报请忽略"
- `run_channel_missing(conn, outbox, *, region, display, business_date, now, table_url, cc_user_ids=(), store_exclude=(), zero_sales_mention=True, at_limit=20) -> TaskOutcome`：
  - **同步门禁（fail-closed）**：先确认本业务日的 dingtalk `channel_daily_sales` 同步批次成功（查 `sync_dataset_summary`，状态 completed 且 `synced_at` 在本次窗口内）；失败/缺失 → `status="skipped_sync_failed"`，**不发消息**，记 ERROR（防止把管道故障误报成门店没填）。
  - 无缺口且无零销售 → `status="all_filled"`，不发消息。
  - 入队 `kind="channel_missing"`，`dedupe_key=qudao:channel_missing:{T-1}`（**不加时分后缀** → 同日只发一条）。
  - @ 人数超 `at_limit` → 只 @ 前 N，其余列文本并抄送 `cc_user_ids`。

## 6. 已知坑（照做，别踩）

- **时区**：`synced_at` 存 UTC；`business_date` 一律按北京时区折算（参考 `extract_channel_ops._business_date_of`）。
- **DictCursor**：`db.connect` 是 DictCursor，**不要 `dict(fetchall())`**（会把单行两列捏成假行），按键取值。
- **pymysql LIKE 字面量必须写 `%%`**。
- **Nacos 为准**：改 `pipelines.seed.yaml` 后必须发布，否则线上不生效；`region-qudao.yaml`（`ccUserIds`、`storeExclude`）由运维在 Nacos 改，真实 robotCode/conversationId 永不入 git。
- **归属口径禁止自造**：一律复用 `extract_ecom_people` 的三级回退。
- **@ 只认 userId**：unionId 直接塞 `atUserIds` 不会生效。
- 群消息 `@` 上限与打扰控制：单日单条、按人聚合、上限 20。
