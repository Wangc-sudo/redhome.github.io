## 3. 锚点（as_of）的四套规则——最易踩的口径差异

| 场景 | 锚点 | 代码位置 |
|---|---|---|
| 本月累计（线下/渠道） | **真实数据水位**（最新有数日），不是今天 | `offline_latest_date` (1042) / `channel_latest_date` (428) |
| 区域/渠道趋势图 | 当前月 = 数据水位；历史月 = 月末 | `_offline_trend_anchor` (1996) |
| 缺口 / 告警 | **今天**（当前月，含当天）；历史月 = 月末 | `_shortfall_as_of` (1988) |
| 日环比 | 最新业务日 | `_OFFLINE_DOD_LATEST_SQL` (970) / `_CHANNEL_DOD_LATEST_SQL` (980) |

设计意图（代码注释原文）：「趋势图不应把 T+1 未入仓的日子画进轴、把未入仓标成 missing；缺口/所需日均仍按今天算」。副作用：同一屏上「已完成」停在 09-24 而缺口按 09-28 算，**缺口系统性偏悲观**（P1-4）。

水位查询的两种口径（刻意不同，勿「统一」）：
- **MTD 卡水位**（`_CHANNEL_LATEST_SQL`，122）：`MAX(business_date) WHERE sales_amount IS NOT NULL`——过滤预填 NULL 行，「最新**有数**日」；
- **日环比卡水位**（`_CHANNEL_DOD_LATEST_SQL`，980）：`MAX(business_date)` 不过滤——「最新**入仓**日」。渠道 DOD 用了后者 → P0-3。

## 4. 逐卡计算逻辑（11 张卡）

### 4.1 `kpi_offline_mtd` 线下本月累计销售

```sql
-- _OFFLINE_MTD_SQL (queries.py:55)
SELECT COALESCE(SUM(sales_amount), 0)
FROM fact_daily_report_offline
WHERE business_date >= DATE_FORMAT(CURDATE(), '%Y-%m-01')
  AND business_date <= %s                       -- 绑定的真实水位
  AND responsible_person NOT LIKE '%合计%'       -- 排除合计行（否则翻倍）
  AND region <> '电商'                           -- ⚠️ 线上无 region='电商' → 过滤失效（P0-1）
```

- 锚点 = `min(月末, 水位)`；空表或水位早于窗口月 → `value=0, as_of=None`（不假装有数）。
- `gran` 四档（`run_kpi_offline_mtd` 1255）：`month`=月首→锚点（缺省）；`day`=锚点当日；`week`=锚点所在自然周（周一首）→锚点；`year`=年首→锚点（`_OFFLINE_YTD_SQL`，84）。带 `month` 参数时锚点=`min(该月月末, 水位)`。
- **实测（09-28）**：`value=83,808,345.31`，`as_of=2026-09-24`。剔除 qudao+vanke 后真值 = **14,892,068.00**（§6.3）。

### 4.2 `kpi_channel_mtd` 电商渠道本月累计销售

```sql
-- 水位 _CHANNEL_LATEST_SQL (122)：MAX(business_date) WHERE <= CURDATE() AND sales_amount IS NOT NULL
-- 求和 _CHANNEL_MTD_SQL (108)：SUM(sales_amount) WHERE >= 月首 AND <= 水位
```

- 水位为 None（空表/全 NULL）→ `value=0, as_of=None`。
- **实测**：`value=35,549,531.91`，`as_of=2026-09-23`。无合计行、无 region 列，只做水位截断。

### 4.3 `kpi_annual_progress` 年度目标达成进度

```
分子 = Σ 各业务线年累计（_ANNUAL_LINE_SOURCES 注册表, 1332）：
  offline   = Σ sales_amount（过滤同 4.1，但窗口 = 年首 → CURDATE()，_OFFLINE_ANNUAL_SQL:95，吃到今天）
  channel   = Σ sales_amount（年首 → CURDATE()，_CHANNEL_ANNUAL_SQL:131）
  restaurant = fact_manual_report(dataset='restaurant_monthly', metric='revenue') 当年 Σ（无行 → has_data=false, 值 0）
分母 = Σ dim_target.annual_target WHERE scope='line' AND year=YEAR(CURDATE())   -- (144)
rate = 分子 ÷ 分母；分母为 0 → rate=null
```

- 注册表外出现的新 `scope_key` → 值 0、`has_data=false` 标红「未接入」——分母不摘除，防静默抹线。
- **实测**：`value=119,357,877.22`、`target=0.0`、`rate=null`（P0-2）。当前 `months` 维度仅 `2026-09`（两事实表只有 9 月数据），YTD≈MTD；线下口径修正后分子应为 14,892,068 + 35,549,531.91。

### 4.4 `trend_region_daily` 区域日销趋势

```sql
-- _REGION_DAILY_SQL (168)
SELECT business_date, region, SUM(sales_amount) AS total
FROM fact_daily_report_offline
WHERE business_date >= 月首 AND business_date <= CURDATE()
  AND responsible_person NOT LIKE '%合计%' AND region <> '电商'
GROUP BY business_date, region
```

- 轴 = 月首 → 锚点（当前月=水位，`_offline_trend_anchor`）的**完整日窗口**；`series`/`status` 与 `dates` 等长；`gran=week`=12 周桶、`gran=month`=12 月桶。
- **逐点三态**（`_align_series_rows` 484，按序判定）：① `d > as_of` → missing；② 全表该日无行 → missing；③ 本系列无行但别家有 → `0.0`+missing（未上报≠真实 0）；④ 有行且 >0 → ok；⑤ 有行且 =0 且覆盖段内有营业日 → zero；⑥ 有行且 =0 且无营业日 → ok。日历未覆盖的月一律降级 ok（宁漏报不误红）。
- **实测**：`as_of=2026-09-24`，5 系列：`hangzhou 7,813,752.00`、`offline_extra 4,841,587.00`、`qudao 68,529,634.31`、`shaoxing 2,236,729.00`、`vanke 386,643.00`；Σ = 83,808,345.31（与卡 1 勾稽 ✅，但同样含 P0-1 污染）。

### 4.6 `table_channel_mtd` 渠道本月对比

```sql
-- _CHANNEL_MTD_COMPARISON_SQL (1089)：BETWEEN 月界 AND <= CURDATE()
SELECT channel, SUM(sales_amount) sales, SUM(promotion_cost) promo,
       COUNT(DISTINCT store_name) stores GROUP BY channel ORDER BY sales DESC
```

- **ROI = Σsales ÷ Σpromo 在 run 层计算**（1735），绝不取行级 roi 源列；`promo` 组内全 NULL → ROI null（「—」）；`promo=0` → 除零护栏 null。

### 4.8 `kpi_shortfall` 目标缺口与告警 ／ 4.9 `anomaly_top` 缺口 TOP10

SQL 只取**事实**（`shortfall_facts` 1886），派生全在 `derived.py`（`shortfall_rows` 1933 组装）：

```sql
-- _SHORTFALL_PEOPLE_SQL (1826)
左表 t（目标）：SELECT responsible_person, MAX(department), MAX(monthly_target)
  FROM fact_daily_report_offline WHERE business_date BETWEEN 月界 [AND region=%s]
  AND responsible_person NOT LIKE '%合计%' GROUP BY responsible_person   -- MAX 子查询不截 CURDATE（目标是月级常量）
右表 d（完成）：SELECT responsible_person, SUM(sales_amount) 同窗口 AND <= CURDATE() GROUP BY responsible_person
LEFT JOIN ON person <=> person；has_fact = (MAX(d.person) IS NOT NULL)    -- 纯诊断字段，不参与分级
```

| 派生列 | 公式（`derived.py`） | 不可算 → None |
|---|---|---|
| `target` | 每人 `MAX(monthly_target)`（区域粒度=Σ各人 MAX） | — |
| `done` | Σ sales_amount（缺事实行按 0） | — |
| `shortfall` | `target − done`，**绝对口径不乘时间进度**（`shortfall` 94） | 无目标 |
| `rate` | `done ÷ target`（`rate` 121） | target ≤ 0 |
| `required_daily` | `target ÷ 当月总工作日`（`required_daily` 107） | 目标/日历缺失 |
| `severity` | p0：`done==0` 且已过 ≥2 工作日；p1：`shortfall ≥ required_daily × 剩余工作日 × 0.5`；p2：`shortfall>0` 未达 p0/p1；ok：`shortfall ≤ 0`（`severity` 179，取最高） | shortfall 不可算 |
| `remaining_workdays` | 严格晚于锚点日的工作日；**已闭月 → None**（历史月不判 p1，退 p2） | — |

- 工作日基数来自 `dim_calendar`（`fetch_workdays`，与日报机器人同口径）：2026-09 total=24、elapsed(含今天)=22、remaining=2。
- 排序键唯一 `shortfall` 降序，缺口不可算者沉底；`anomaly_top` = 同口径前 10（`_ANOMALY_TOP_N=10`），`rank` 服务端给、前端不重排；URL 暂不开放 `grain` 参数。
- **实测**：65 行、severity 分布 p1×44 / p2×1 / ok×19 / None×1；65 行全部派生列独立复算 **0 处不一致** ✅；TOP10 与大表前 10 完全一致 ✅。但 65 人中含 23 名电商人员（done Σ=68,529,634.31 = qudao 口径）——P0-1 连带污染。

### 4.10 `kpi_offline_dod` 线下日环比 ／ 4.11 `kpi_channel_dod` 电商日环比

```
latest = MAX(business_date)（线下：排除合计行 + region<>'电商'；渠道：不过滤 NULL ⚠️ P0-3）
totals = 按日 Σsales，窗口 [latest-6, latest]（_dod_totals 1009；近 7 自然日）
value = totals[latest]；prev = totals[latest-1]   -- 基期 = 前一「自然日」，不是前一「数据日」
delta_pct = (value − prev) ÷ prev；prev 缺失或 0 → None（「—」，绝不显示 0%）
trend7 = [latest-6 .. latest] 的 {date, value}（缺数日 value=null）
```

- **实测**：线下 `date=09-24`，`775,156.00` vs `2,741,467.96` → **-71.72%**（复算一致；但分母含 qudao 口径 → 数值本身失真）；渠道 `date=2026-09-28` **整卡全 null**（P0-3）。

## 7. 缺陷清单与修复建议（按优先级）

### 🔴 P0-1 线下口径混入电商集合口径数据（虚增 462.6%）

- **现象**：首页「线下本月累计」= 83,808,345.31，真值 14,892,068.00，**虚增 68,916,277.31**（qudao 68,529,634.31 + vanke 386,643.00）。
- **连带污染**（同一过滤 `_OFFLINE_LINE_SQL` 出现在 6 处 SQL）：`trend_region_daily`（qudao 系列占趋势 81.8%）、`kpi_offline_dod`（-71.72% 由渠道口径驱动）、`kpi_annual_progress` 线下线分子、`kpi_shortfall`/`anomaly_top`（23 名电商人员混入，TOP10 占 9 席）。
- **根因**：`queries.py:49` `_OFFLINE_LINE_SQL = "AND region <> '电商'"`，而线上 region 全集无「电商」值。该代码写于 B3（2026-09-20 业务裁定「region=电商 归电商线」），与实际入库的 `qudao` 值不匹配——**代码口径与入库数据脱节**。
- **已实施（2026-09-28）**：保留黑名单形态、修正名单——
  ```python
  # queries.py（原 :49，行号随注释展开微移）
  _OFFLINE_LINE_SQL = "AND region NOT IN ('电商', 'qudao', 'vanke')"
  ```
  同时 `shortfall_facts` 缺省（无 region 参数）注入同一过滤；显式选 region（l2-ecom-people 选 qudao）逐字透传不受影响；`_SHORTFALL_REGION_SQL`（grain=region）同步。
  **未采用 §6.3 初稿建议的白名单 `region IN ('hangzhou','shaoxing','offline_extra')`**，理由：①白名单会把「新区域上线默认计入线下」的原设计意图翻转为默认静默丢数；②显式选区（含集成测试的夹具区域）会被白名单交集成空集。黑名单修名单两风险皆无。
  ⚠️ `vanke`（体验馆，38.66 万）暂按 offline_all 页「线下整体」口径排除，**是否计入仍待业务裁决**（`BI建设指南.md` 待确认清单 #7）；若裁决纳入，把它移出名单即可（预期值变 15,278,711.00）。
- **验收**：`kpi_offline_mtd` 应 = 14,892,068.00，完成率与 offline_all.html 79.0% 对拍一致；缺口卡不再出现直播/猫超等部门人员（65 行 → 42 行非电商人员）。
- **回归**：`test_bi_web_queries.py` 新增 `ShortfallDefaultLineTests`（缺省含排除名单 / 显式透传不含）+ region-grain 形状断言 + `_LINE_EXCLUSION` 常量更新；bi-web 单测 471 例全绿（1 失败为另一批在途 auth 改动的存量问题，与本修复无关）。

### 🔴 P0-2 年度目标分母为 0

- **现象**：`kpi_annual_progress` → `target=0.0, rate=null`，三线 target 全 0，卡片事实上失效。
- **根因**：`dim_target` 表内**没有** `scope='line' AND year=2026` 的行（种子样例有 769,510,000 量级，线上库未灌）。
- **修复建议**：由业务给出 2026 年度三线目标后落库（offline/channel/restaurant 各一行 `scope='line'`）；灌库前该卡可先在 seed 里置 `enabled` 或标注「待目标数据」，避免误导。P0-1 修复后分子同步变正确。

### 🔴 P0-3 电商渠道日环比整卡全空

- **现象**：`kpi_channel_dod` → `date=2026-09-28`（今天），value/prev/delta_pct 全 null，trend7 仅 09-22/09-23 有值。
- **根因**：`_CHANNEL_DOD_LATEST_SQL` (980) 取 `MAX(business_date)` **未过滤 `sales_amount IS NOT NULL`**——渠道 extract 预填了 09-24 起整周 NULL 行，水位虚报到 09-28；窗口 [09-22, 09-28] 内 09-24~09-28 无数据行 → null。
- **已实施（2026-09-28）**：对齐 `_CHANNEL_LATEST_SQL` 口径，加 `AND sales_amount IS NOT NULL`；`test_channel_dod_sql_shape` 补 `assertIn("sales_amount IS NOT NULL", latest_sql)` 钉死。
- **验证预期**：`date` 应回到最新有数日（当前数据应为 2026-09-23），环比基期=09-22，恢复可用。
- **关联**：线下水位 `_OFFLINE_DOD_LATEST_SQL` 不过滤 NULL 是安全的（线下日报当前无预填），但代码注释已预警「若线下未来也预填，应对齐本口径」——建议一并统一，消除同类隐患。

### 🟠 P1-4 锚点口径不自洽（缺口悲观偏差）
