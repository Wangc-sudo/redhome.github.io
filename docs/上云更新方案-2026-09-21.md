## §0 微服务文章评估结论（《云原生之微服务架构》，腾讯云社区 2211475）

该文是 Spring Cloud / 华为 CSE 的理论入门笔记。**结论：不采纳其架构方向，理由即该文自己的论述**：

| 文章观点 | 对我们的适用性 |
|---|---|
| Spring Cloud 微服务（Eureka/Hystrix/Zuul…） | ❌ 作者明言「仅限 Java、SDK 侵入性强、**不适合小型独立项目**」——我们是 3 台 ECS 的内部运营系统，且语言栈为 Python |
| 微服务六大要素：RPC / 注册发现 / 分布式事务 | ❌ 服务拓扑固定（bi-web / gateway / robot / pages），无需注册发现与 RPC；无跨服务事务 |
| 配置外置 | ✅ **已落地**（Nacos 承载 PIPELINES / REGIONS / BI 三组），无需改造 |
| 微服务治理（熔断/限流） | ✅ 已有轻量等价物：配置链 fail-open、outbox 重试、网关超时纪律 |
| 可观测性（链路追踪 + 集中日志） | 🟡 **是真实短板**，借上云补齐（见 §2.4）：`sync_runs` / `robot_outbox` 状态 + 云监控告警，不引 APM 重型方案 |
| 华为 CSE 托管微服务引擎 | ❌ 不采纳：CSE 面向 Spring Cloud/Dubbo 应用；其托管 Nacos 对我们 standalone 单点场景是成本与 vendor 绑定的过度方案。自建 Nacos（ECS-Ctrl）维持原规划 |

> 一句话：文章可留作团队概念读物，零代码影响；「可观测性」是唯一转化为行动项的条目。

### 2.2 Redis 访问控制（替代原 §3.1 白名单）

天翼云分布式缓存（DCS）无阿里云式白名单，访问控制 = **VPC 安全组 + 实例访问密码**：

- DCS 实例安全组仅放行三台 ECS 内网 IP 的 6379（或放 vpc-e82d 网段）；
- 创建实例时设置的密码注入 `PUBLIC_DATA_REDIS_URL=redis://:<密码>@192.168.0.6:6379/0`；
- 验收命令三台同跑（密码从仓库外凭据取，不落文档）：

```bash
python3 -c "import redis;r=redis.Redis(host='192.168.0.6',port=6379,password='<凭据取>',socket_connect_timeout=20);print(r.ping())"
```

### 2.4 可观测性补齐（文章唯一转化项，轻量做法）

- **告警源 1（数据面）**：cron 包一层巡检脚本，每日核对 `sync_runs`（无 failed/projection_pending）与 `robot_outbox`（无超龄 failed），异常发钉钉群 webhook；
- **告警源 2（云侧）**：天翼云云监控对三台 ECS 配 CPU/内存/磁盘基础告警 + RDS 连接数/存储告警，通知到运维；
- **日志**：容器日志 `json-file` + 轮转（max-size 10m ×3），不引集中式日志系统；
- 以上均为运维配置，**零代码改动**（巡检脚本复用 `mart_cli` 只读查询，一行写入也没有）。
