# 云迁移指南（GitHub + CI/CD）

本仓库已按"随时可上云"设计。迁移步骤：

## 1. 前置检查（已满足）

- [x] 代码位置无关：所有脚本用 `Path(__file__).parent` 定位配置，目录可整体搬迁
- [x] 依赖纯标准库（miniconda3 Python 3.10+ 均可运行），无 pip 依赖
- [x] 机密不入库：`config.json` / `wdt_credentials.json` 已 gitignore，仓库只含模板
- [x] CI 已预置：`.github/workflows/ci.yml`（语法编译 + 配置模板校验，只读不碰钉钉）

## 2. 迁移到 GitHub

```bash
# 安装 gh CLI 后（winget install GitHub.cli），浏览器授权：
gh auth login

# 本仓库推送到 GitHub（私有仓库）：
cd /d/repos/digital-ops
gh repo create digital-ops --private --source=. --push
```

推送后 CI 自动生效（push/PR 触发）。

## 3. 云端 CI 与本机 CD 的边界

脚本运行依赖**本机 dws 凭据、钉钉 AI 表格、千问办公桌面端**，因此：

| 环节 | 位置 | 说明 |
|---|---|---|
| 代码检查 / 语法 / 配置校验 | GitHub Actions（云端） | CI 只读，不碰真实数据 |
| 定时执行 / 发消息 / 写表 | 本机（千问办公 cron） | 凭据在本机 |
| 页面发布 | 本机（QW Pages） | 桌面端受控发布 |

## 4. 迁移后的部署流程（推荐）

1. 本机新增 07:50 同步任务：在 `D:\repos\digital-ops` 执行 `git pull --ff-only`
2. 08:30 榜单等定时任务不变（脚本路径已指向本仓库），拉到什么跑什么
3. 合并到 main 即视为部署；回滚 = `git revert`，次日 07:50 生效

## 5. 注意事项

- 中文目录路径在 git 中正常支持；若云端 runner 报编码错误，在 workflow 中加 `env: PYTHONIOENCODING: utf-8`
- `config.json` 换机器部署时需手工复制（不进 git 历史，避免 appSecret 泄露）
- 若未来把执行迁到云服务器（如 ECS），参考 `渠道日报机器人/README_ECS部署指南.md`；但钉钉凭据与 QW Pages 发布仍需单独处理
