# 渠道日销机器人填报机制方案（region=qudao）

- 日期：2026-09-29
- 前置：`渠道日销T+1采集与门店到齐催办方案-2026-09-28.md`（催办侧）、`渠道日销门店催办-P0探针报告-2026-09-29.md`（No-Go 结论）
- 性质：对 09-28 方案的**修订增补**——把"手工 AI 表台账"替换为"群内机器人填报"，催办逻辑（`channel_missing.py`）零改动复用

## 1. 背景与已定裁决

P0 探针证实：
- 填报链 09-24（中秋前一天）起停止，全渠道最后真实填报=09-23；sync 管道健康但源静止（每批 `raw_records_written=0`）；
- 19 位渠道负责人不在本企业钉钉组织（unionId/姓名双链路零命中），自动 @ 不可行；
- AI 表填报模式存在结构性弱点：依赖预置行、节假日无人维护即静默停摆、`NULL 行/无行`两态难辨。

**运维裁决（2026-09-29）**：
1. 19 位负责人在钉钉同一通讯录（= 都在渠道群内，可群内填报；@ 仍走文本点名）；
2. 填报格式**统一**：一条（行）一店一金额；
3. 同意按本方案落地。

## 2. 总体设计

```
渠道群消息（region=qudao）
   │  「京东 习水村 15867」
   ▼
stream_handler（按 conversationId 路由）
   ▼
channel_intake（新增，镜像 report_intake 模式）
   ├─ 解析：按行，[日期] [渠道词] 店名关键词 金额
   ├─ 写 inbox：channel_sales_robot_inbox（append-only）
   └─ 回执：✅ 已记录 + 覆盖提示 + 渠道当月进度
                │
extract-mart（channel_daily_sales 分支加合并步）   ◄── AI 表 sync 保留（兜底源）
   │  业务键 (business_date, channel, store_name)：inbox 最新行优先，AI 表行兜底
   ▼
fact_channel_daily_sales  ──► 10:31 到齐催办（零改动）／qudao.html（零改动）
```

**为什么走 inbox + extract 合并，而不是 report_intake 的直写 fact**：
`fact_channel_daily_sales` 的 extract 是**全量 DELETE+INSERT**（`extract_mart.py` replace 路径），直写行会在下次 extract 被抹掉。线下日报能直写是因为其 AI 表 sync 已退役；渠道侧 AI 表 sync 保留作兜底，过渡期必须双源共存——inbox 是真源，extract 负责汇合，任何时刻重跑 extract 数据不丢。

## 3. 填报协议（给填报人）

| 写法 | 含义 |
|---|---|
| `京东 习水村 15867` | 默认报**昨天**（T-1，与 10:31 采集口径一致） |
| `9.27 天猫 酒旗 82059` | 带日期前缀 = 补填指定日（最长追溯 30 天） |
| `朴朴 118038` | 渠道词可省（店名全册唯一即可） |
| `猫超 731033` | 渠道级填报（仅空店铺名渠道开放，store_name=NULL） |
| `私域 0` | 0 合法（= 已填报零销售，与现行口径一致） |
| 一条消息多行 | 每行独立一条，逐行回执汇总 |

解析规则（纯逻辑，全部可单测）：
1. **按行**处理；剥 `@机器人` 前缀与零宽字符（复用 `parse_aux_command` 手法）；
2. 金额：复用 `parse_report_amount` 规则（千分位/全角逗号/小数）；**行尾最后一个数字为金额**；
3. 日期前缀：`9.27 / 9-27 / 9/27 / 9月27`（复用 `_parse_backfill_date` 年份回推逻辑，未来日/超 30 天拒绝）；
4. 店名：名册 = `fact_channel_store_target` 全 32 店（T4 已证 A=B 重合）；输入词与店名做**包含互查**（输入⊂店名 或 店名⊂输入），候选唯一 → 认；带渠道词时先按渠道过滤再匹配（`京东 习水村` 只在京东 5 店里选，大幅降低歧义）；多候选 → 回候选列表；无候选 → 格式提示；
5. 渠道词：`京东/天猫/拼多多/直播/即时零售/私域/猫超`；单独出现且无店名命中时，仅**猫超**允许渠道级填报，其他渠道提示补店名；
6. 覆盖语义：同 `(business_date, channel, store_name)` 重发即覆盖（inbox 追加新行，extract 取 `created_at` 最新）——**改数 = 重发一条**，无编辑概念；
7. `/` 开头一律走辅助指令，不进填报解析（防误录，同 report_intake）。

## 4. 身份与门禁

- **门禁 = 群成员**：凡 qudao 群成员均可填报；**不查 `dim_robot_member`**（19 位负责人不在本企业组织，这是与 report_intake 的核心差异）；
- 路由按 `conversationId` 锁定渠道群（复用 `region_for_conversation`），外群消息天然进不来；
- 每条 inbox 记录 `sender_userid` + 原文（审计可追溯"谁填的"），姓名从消息回调尽力携带；
- **代填天然支持**：店名在文本里、不依赖 sender 归属——渠道对接人（本企业员工）可代全渠道填报，与门店自填同一通道；
- 管理代录/改他人历史：直接重发同店同日即可（覆盖语义），不另设 /补签。

## 5. 数据模型

### 5.1 inbox 表（mart_ops 库，gateway 已有连接）

```sql
CREATE TABLE `channel_sales_robot_inbox` (
  `id` BIGINT NOT NULL AUTO_INCREMENT,
  `conversation_id` VARCHAR(64) NOT NULL,
  `sender_userid` VARCHAR(64) DEFAULT NULL,
  `sender_name` VARCHAR(128) DEFAULT NULL,
  `raw_text` TEXT NOT NULL,
  `channel` VARCHAR(50) NOT NULL,
  `store_name` VARCHAR(255) DEFAULT NULL,        -- NULL = 渠道级（猫超式）
  `business_date` DATE NOT NULL,
  `sales_amount` DECIMAL(20,4) NOT NULL,
  `status` VARCHAR(16) NOT NULL DEFAULT 'parsed', -- parsed / rejected
  `reject_reason` VARCHAR(255) DEFAULT NULL,
  `created_at` DATETIME(6) NOT NULL,
  PRIMARY KEY (`id`),
  KEY `idx_biz` (`business_date`, `channel`, `store_name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4
```

迁移版本：`mart-ops-channel-robot-inbox-v1`（入 `live_migrations.py`）。拒绝行也落（status=rejected），支撑"解析失败率"运营观察。

### 5.2 extract 合并规则（`extract_mart` channel_daily_sales 分支）

1. 照旧从 raw AI 表构建行；
2. 取 inbox `status='parsed'` 行，按 `(business_date, channel, store_name)` 归组取 `created_at` 最新；
3. **inbox 行覆盖同业务键 AI 行**（含把 NULL 覆盖成值），AI 独有业务键保留；
4. inbox 来源行 `source_record_id = robot:{inbox.id}`、`sync_run_id = STREAM_RUN_ID`（全零，审计可辨），`responsible_person = NULL`（归属回退月目标表 owners_json，`channel_missing.owners_for` 已支持）；
5. 摘要行如实记录合并计数（`records_read` 含 inbox 行数）。

## 6. 回执文案

```
✅ 已记录 9月28日 渠道日销：
京东·JD习水村习酒专卖店：15,867（识别：习水村）
📊 京东 本月累计 191.2万 / 目标 315万，完成 60.7%
填错了重发一条即可覆盖～
```

- 覆盖旧值时加 `（🔁 覆盖旧值 12,300）`；
- 渠道月进度复用 `fetch_channel_dept_rollup`（自然日 MTD 口径，与 qudao.html 一致）；
- 歧义：`「习水村」匹配到多家店：京东-JD习水村习酒专卖店 / 京东-JD习水村酒类专营店，请带上渠道词或写全店名`；
- 失败：通用提示 + 格式示例（不插值异常原文，同 report_intake 纪律）。

## 7. 与既有能力的关系

| 能力 | 改动 |
|---|---|
| 10:31 到齐催办 `channel_missing` | **零改动**——fact 里 robot 行自然消除缺口；全齐静默 |
| qudao.html / MTD 口径 | **零改动**——同读 fact |
| AI 表 sync（每日 4 批） | 保留，降级为兜底源；观察 1 个月后可议退役 |
| `/辅助` 指令族 | 本期不接渠道群（避免混语义）；`/未填` 渠道版列入 P2 |
| fail-closed 同步门禁 | 保留（防 AI 表管道故障误判）；inbox 写入不在门禁内 |

## 8. 为什么这比 AI 表简单（三方视角）

- **填报人**：群里一句话，有即时回执；不用开表、找 sheet、翻预置行；填错重发即改；
- **运维**：零预置行维护；名册=月目标表自动同步；节假日停摆会变成**显式缺口**（催办/报表可见）而非静默 NULL；
- **系统**：数据只来自"有意识的填报动作"，缺口语义干净；AI 表 schema drift 风险隔离在兜底源。
