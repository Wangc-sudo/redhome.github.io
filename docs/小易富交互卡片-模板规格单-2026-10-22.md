## 二、模板搭建规格

模板用途：**商品资料卡**（单款商品命中时发送）。

### 2.1 卡片内容区（变量绑定）

| 模板变量 | 类型 | 说明 | 示例 |
|---|---|---|---|
| `title` | 文本 | 商品名 | 习酒窖藏1988 |
| `image` | 图片 | 商品主图 URL | （细节图第一张） |
| `params_md` | markdown | 参数正文（箱规/度数/规格等） | 箱规：6 瓶/箱… |
| `record_id` | 文本 | 商品记录 ID（**按钮回传要用，不展示**） | recXXXX |
| `has_detail` | 文本 | "1"/"0" 有无细节图附件 | 1 |
| `has_report` | 文本 | "1"/"0" 有无质检报告附件 | 1 |

（`has_*` 用于控制按钮显隐；平台不支持条件显隐就固定全显，代码侧按实际
附件有无如实降级。）

### 2.2 按钮区（关键：交互行为必须选「回传请求 request」）

| 按钮文案 | 交互行为 | privateData（回传负载） |
|---|---|---|
| 📷 发我细节图 | 回传请求 | `{"kb_action":"asset","field":"细节图","record_id":"${record_id}"}` |
| 📄 发我质检报告 | 回传请求 | `{"kb_action":"asset","field":"质检报告","record_id":"${record_id}"}` |
| 🖼 发我图片素材 | 回传请求 | `{"kb_action":"asset","field":"图片素材","record_id":"${record_id}"}` |

要点：
- 交互行为选「**回传请求（request）**」，**不要**选「跳转链接」——跳转
  链接不会产生回调（PoC 已实测）。
- privateData 里的 `${record_id}` 绑定 2.1 的模板变量，发卡时由代码注入，
  用户点击后平台把插值后的 privateData **原样回传**给我们。
- `kb_action` 是回调路由键，固定值 `asset`（后续要加新按钮动作就加新键）。

## 三、回调数据契约（我方已实现的解析口径）

回调报文里按钮负载的路径（PoC 实测结构）：

```
content.cardPrivateData.action.privateData  →  上面的 privateData JSON
content.openConversationId                  →  会话（群/单聊）
userId                                      →  点击人
outTrackId / content.cardInstanceId         →  卡片实例（就地更新用）
```

我方行为契约：
- 收到 `kb_action=asset` → 按 `record_id`+`field` 查附件 → 直发文件/图片
  到当前会话 → 把原卡片按钮区更新为「✅ 已发送」状态（不刷屏）。
- 任一环节失败 → 卡片更新为降级提示，不影响问答主链路。
