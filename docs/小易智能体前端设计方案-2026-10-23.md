# 小易智能体 Web 前端设计方案

> 2026-10-23　　状态：方案待裁决　　定位：小易（kb-qa 知识库问答机器人）的
> Web 对话入口——聊天窗形态，钉钉 H5 免登进入，客服在钉钉工作台/群内链接
> 点开即用。
>
> 关联裁决：卡片路线搁置（不做），聊天里保持纯文本；Web 前端是浏览/深聊/
> 下载附件的主场。本文档是**完整设计**（框架/交互/对话窗/侧边栏/后端），
> 裁决后按 §9 分期实施。

---

## 1. 产品定位与信息架构

一句话：**公司内部的 ChatGPT 式对话页**，数据来自小易已有的知识库与业务
数据通路（商品/手册/区域日销/渠道日销），不是另一个管理后台。

```
┌──────────────────────────────────────────────────┐
│ 顶栏：小易 logo + 名称 + 用户头像（免登带入）        │
├──────────┬───────────────────────────────────────┤
│ 侧边栏    │ 对话区                                 │
│ ┌──────┐ │  ┌──────────────────────────────┐     │
│ │+新对话│ │  │ 助手气泡（markdown/表格/图片）  │     │
│ └──────┘ │  └──────────────────────────────┘     │
│ 今天      │  ┌──────────────────────────────┐     │
│ · 习酒箱规│  │ 用户气泡（右对齐）              │     │
│ · 茅台工艺│  └──────────────────────────────┘     │
│ 昨天      │           …（滚动）                   │
│ · 渠道日销│  ┌──────────────────────────────┐     │
│ 更早      │  │ 输入框 [发送] [常用问题›]      │     │
│ · …      │  └──────────────────────────────┘     │
└──────────┴───────────────────────────────────────┘
```

- **侧边栏**（可折叠，移动端抽屉式）：新对话按钮 + 会话历史列表
  （按 今天/昨天/更早 分组，标题=首条问题截断），点击切换会话，长按/悬停
  出现重命名与删除。
- **对话区**：消息流 + 输入框。空会话时显示**引导页**（小易简介 + 4-6 个
  常用问题卡片，点击即发问）。
- **顶栏**：品牌区 + 用户身份（免登带入的姓名/头像）+ 反馈入口。

## 2. 技术选型（全部复用现有栈，零新框架）

| 层 | 选型 | 理由 |
|---|---|---|
| 前端框架 | **Vue 3 + Vite + TS** | 与 ops-web 完全同栈，组件/构建/CI 管线现成 |
| 样式 | 手写 CSS（仿 bi-web 的轻量设计系统） | 不引 UI 库，保持包体小、风格与看板一致 |
| markdown 渲染 | 轻量渲染器（复用/裁剪 bi.js 的渲染面或引入 marked 级小库） | 小易答案含表格/列表/加粗 |
| 流式 | **SSE（EventSource 不行就用 fetch ReadableStream）** | 钉钉 WebView 兼容良好；WebSocket 不必要 |
| 后端 | **FastAPI 挂在 bi-web**（新增 /kb 路由组） | bi-web 已有会话/免登/authz/nginx 反代全套路 |
| 会话存储 | **Redis**（kbqa:web:sess:* 键族，TTL 7 天） | 10-22 刚打通，原生 TTL 免清理 |
| 身份 | **钉钉 H5 免登** | bi_web/auth.py 的 DingTalkAuthClient + HMAC session 全是现成的 |

## 3. 对话窗设计（核心交互面）

### 3.1 消息气泡

- **用户消息**：右对齐，纯色气泡，纯文本。
- **助手消息**：左对齐，宽气泡，内容按类型渲染：
  - markdown 正文（标题/加粗/列表/表格）
  - **商品卡内嵌块**：命中商品时答案里的商品以卡片样式呈现（图+名+关键
    参数），卡片上放「查看附件 ›」链接跳到消息内附件区
  - **附件列表块**：细节图/质检报告等，图标+文件名+大小，点击直接下载
    （后端现取签名 URL 302 跳转，前端不碰时效逻辑）
  - **数据表块**：业务数据答案（日销/渠道）以斑马纹表格呈现
  - **来源标注**：手册类答案末尾的【引自《XX》】渲染为浅灰小字
- **失败/降级**：兜底话术用同一气泡形态，不暴露异常。
- **消息操作条（V1）**：每条助手气泡底部一排小图标按钮——
  - **复制**：一键复制答案全文（客服的核心动作是把答案转给客户，
    手机长按复制体验差，必须给按钮）；
  - **转发到钉钉会话**：调 `dd.shareToChat` 直接转发给客户/同事；
  - **重新生成**：同问题重答一次（坏答案有出口），后端走幂等重放；
  - **引用追问**：把该条答案带入下一条提问的上下文锚点。

### 3.2 思考过程与耗时反馈（2026-10-23 补充裁决：方案完整度项）

等待不是黑盒——用户能看到小易「在想什么、进行到哪步、花了多久」。

- **等待态（V1 必备）**：助手气泡立即出现，显示「小易思考中… 已用 Xs」
  递增计时（本地秒表即可，不等后端）。>10s 追加安抚文案「数据量较大，
  正在仔细查询」。
- **工具步骤条（V1 必备）**：agent 路径下逐步显示已完成的工具调用——
  「✓ 查了商品库」「✓ 查了区域日销」「✓ 正在写回答…」。原料现成：
  agent 的 meta.tools/rounds 已在审计层落库（#203），后端只需把它透进
  响应。非 agent 路径显示单步「✓ 检索完成」。
- **思路折叠区（V2，随 SSE）**：推理版模型（deepseek-v4.1-flash）的
  reasoning 以「思路 ›」折叠条呈现在答案上方，默认收起、可展开只读；
  实现=LlmClient 增加 reasoning_content 捕获（现只取 content，扩展点
  明确）+ SSE 新增 thinking 事件类型。折叠区不参与会话历史回喂。
- **耗时落款（V1 必备）**：答案气泡右下角浅灰小字「共 X.Xs · N 次查询」
  ——latency_ms 已在审计层，响应里带回来即可。
- 心理收益：业务查询（agent 多轮工具）实测 3-9s，无反馈会被当成
  「卡死/没收到」；有步骤条+计时后等待可感知、可信度上升。

### 3.3 输入区

- 多行自适应输入框（Enter 发送 / Shift+Enter 换行，移动端独立发送键）。
- 发送中状态：输入框禁用 + 助手气泡进入 §3.2 思考态；SSE 流式开启后
  逐字上屏，思考态转为光标。
- **常用问题**：输入框上方一排可横滑的建议词（换一批按钮），空会话时
  放大为引导卡片。

### 3.4 流式与状态

- V1 先非流式（请求-响应 + §3.2 思考态），**但 API 按 SSE 设计**（见 §5），
  V2 开关即开流。
- SSE 事件类型（V2）：`status`（工具步骤推进）/ `thinking`（推理增量，
  进折叠区）/ `delta`（正文增量）/ `done`（含 latency/token 汇总）。
- 中断：流式时显示「停止」按钮（关闭 SSE 连接即可，后端可感知断流）。

## 4. 侧边栏与会话模型

- **会话 = session**：（userid, session_id）为键，Redis 存消息列表
  （user/assistant 交替，带时间与 meta），TTL 7 天滑动。
- **标题自动生成**：首条用户消息截 18 字；重命名走 inline 编辑。
- **历史即上下文**：Web 会话的历史直接复用 kb_qa 对话层语义（最近 6 轮
  进 LLM），但存储从「10 分钟 TTL」改为「会话存续期」——Web 场景用户
  期待回来还能接着聊，与群内短上下文是两种产品语义，两套参数。
- 删除会话 = 删 Redis 键；上限每用户 50 会话（超出淘汰最旧）。

### 4.1 记忆层决策（2026-10-23 裁决讨论：不引入自动长期记忆）

小易的记忆分三层，本方案只要前两层：

| 层 | 形态 | 生命周期 | 本方案 |
|---|---|---|---|
| 会话内上下文 | 最近 6 轮进 LLM prompt | 群内 10 分钟 / Web 会话存续期 | ✅ 已有 |
| 会话历史 | Redis 消息列表 | 7 天滑动 | ✅ V1.5 |
| 跨会话长期记忆 | LLM 自动抽取用户事实存库、召回注入 | 永久 | ❌ **不做** |

不做第三层的理由：
1. **场景不匹配**——客服提问是事务性查询（箱规/价格/质检报告），正确
   答案取决于知识库数据而非「这个用户上次问过什么」，长期记忆对问答
   精度几乎无增益；
2. **风险大于收益**——自动抽取会记错（幻觉沉淀为「事实」），一条错误
   记忆会持续带偏后续回答且难以察觉；
3. **成本不成比例**——抽取调用、存储、召回注入、遗忘策略是一整条
   独立子系统。

若未来要个性化，走**画像与收藏**（不做记忆）：用户手工/半自动维护的
确定信息（姓名部门、收藏商品、常用问题置顶），可读可改可删，零幻觉
风险。作为 V3+ 候选记录，不占本方案分期。

## 5. 后端 API 设计（bi-web 新增 /kb 组，全部需会话）

```
GET  /kb/api/bootstrap           → 免登态检查 + 用户信息 + 引导配置
POST /kb/api/auth/dingtalk       → {authCode} 换 session（复用 auth.py）
GET  /kb/api/sessions            → 会话列表（按更新时间倒序）
POST /kb/api/sessions            → 新建会话 → {session_id}
GET  /kb/api/sessions/{id}       → 会话全量消息
POST /kb/api/sessions/{id}/messages  → {content} → SSE 流式应答
                                       （V1 跑通后 Accept: text/event-stream）
                                       响应含 meta：{tools, rounds, latency_ms}
                                       （§3.2 工具步骤条与耗时落款原料）
DELETE /kb/api/sessions/{id}     → 删除
PATCH  /kb/api/sessions/{id}     → 重命名 {title}
POST /kb/api/sessions/{id}/regenerate  → 重放末条用户消息（重新生成按钮）
GET  /kb/api/attachments/{record_id}/{field}/{idx}  → 302 到新鲜签名 URL
```

关键复用点：**小易的问答主链路 `_answer(conn, text, history, meta)` 本来就是
通道无关的纯函数**——Web 通道只是新的调用方，把 Redis 会话历史转成
history 传进去，回答、附件、agent 工具、token 统计全部原样生效。审计走
同一 `kb_qa_audit`（intent 记录照旧，channel 维度可加一列区分 web/dingtalk，
V2 再说）。

## 6. 免登链路（钉钉 H5）

```
钉钉内打开 https://dt.yyhlzj.com/kb/
  → 前端 dd.runtime.permission.requestAuthCode（JSAPI）
  → POST /kb/api/auth/dingtalk {authCode}
  → 后端 exchange_auth_code 换 userid（auth.py 现成）
  → 签 HMAC session cookie（8h 滑动，现成）
  → 进入对话页
```

- 钉钉外（浏览器直接打开）→ 显示引导页「请在钉钉中打开」（auth-entry
  模式复用）。
- **开发者后台要做的事**（运维清单，见 §10）：小易应用加 H5 微应用能力、
  首页地址填 `https://dt.yyhlzj.com/kb/`、JSAPI 安全域名加 `dt.yyhlzj.com`。

## 7. 附件下载链路

AI 表签名 URL 有时效，**不落前端**：
`GET /kb/api/attachments/...` → 后端 get_record 现取签名 URL → 302。
图片缩略图同理（V2 可加本地缓存，media.py 的 kb_media_cache 思路平移）。

## 8. 非功能设计

- **移动端优先**：客服全在钉钉手机端；390px 视口为一等公民（侧边栏变
  抽屉、输入框吸底、气泡 92% 宽）。桌面端居中限宽 860px。
- **性能**：首屏 < 100KB gzip（无 UI 库）；会话列表懒加载。
- **安全**：session HMAC（现成）、API 全要会话、附件接口校验会话、
  SQL 全占位符（沿用 kb_qa 纪律）、错误响应泛化。
- **弱网兜底（V1）**：钉钉 WebView 弱网常见——请求 15s 超时友好提示 +
  自动重试一次；发送失败的消息本地暂存可一键重发；会话列表/历史失败
  降级空态不白屏。
- **答案缓存（V2）**：高频相同问题（归一化问法）Redis 短 TTL 缓存
  直接命中，省 token 提速；数据类问题（日销）不缓存或极短 TTL，
  商品资料类缓存 10 分钟。
- **可观测**：token 统计已有（#211）；Web 通道消息进同一审计表。

## 9. 分期路线（2026-10-23 裁决：优化方向全面纳入，成本不设限）

| 期 | 内容 | 出口标准 |

| **V1** | 免登 + 单会话对话页（非流式）+ markdown/表格渲染 + 附件下载 + 移动端适配 + 思考态（计时+工具步骤条）+ 耗时落款 + **消息操作条（复制/转发 dd.shareToChat/重新生成/引用追问）** + **弱网兜底** | 客服群 3 人试用一天无阻断性问题 |

## 10. 需要运维/管理员配合的事项（开工前一次性）

1. 开发者后台：小易应用加 **H5 微应用**能力，首页地址
   `https://dt.yyhlzj.com/kb/`；
2. JSAPI 安全域名加 `dt.yyhlzj.com`；
3. （免登权限）确认应用有「通讯录个人信息读」权限点；
4. nginx：`/kb/` 路径反代到 bi-web（参照 hangzhou.html 既有白名单模式）；
5. **业务数据权限面裁决（开工前置，用户决策）**：agent 工具可查区域/
   渠道日销等经营数据，群内现状是全开放；Web 前端上架前需裁决客服
   是否可见经营数据——三选一：全开放（现状平移）/ 按部门或角色白名单
   （bi_authz 现成体系可复用）/ Web 通道屏蔽业务数据工具（只答商品
   与手册）。

## 11. 验收标准（V1）

1. 钉钉内点开即进入对话页，无登录页、无密码；
2. 问「习酒窖藏1988 箱规」→ 3s 内出 markdown 答案；
3. 追问「价格呢」→ 上下文接续正确（Redis 会话历史）；
4. 问「质检报告」→ 答案里附件链接点击可下载；
5. 钉钉外打开 → 引导页；390px 手机视口无横向滚动；
6. 气泡操作条：复制全文一键完成、转发可调起钉钉分享、重新生成
   返回新答案；
7. 断网/超时场景有友好提示与重发，不白屏不丢已输入文字。
