# 电商渠道日报升级设计：商品动销仪表盘 + 播报并入（杭绍同形）

状态：设计定稿（2026-09-23，运维需求口述整理）
关联：`2026-09-22-de-ai-table-db-single-source.md`（去表格总路线）、
`extract_ecom_people.py`（人员归属口径）、`渠道日报机器人/channel_report.py`（旧播报）

---

## 0. 需求与约束（运维原话口径）

1. 在**现有电商渠道日报表（AI 表）**内增加「商品动销仪表盘」，不建新系统：
   热销总榜、分品牌热销榜、分渠道热销榜；指标 = 商品累计销售额、昨日销售额、环比。
2. 旧电商播报**并入**「电商渠道日报」播报，**形式与杭州、绍兴一致**（同三件套时刻）。
3. 播报里加入**人员排名**与**任务进度**。
4. 红线：**保障之前的功能不变**，只做加法。

## 1. 商品动销仪表盘（AI 表内，alidocs 原生仪表盘）

### 1.1 数据基础：新增「渠道SKU动销」sheet（业务侧维护）

在现有电商渠道日报表 base 内加一张 sheet，店铺后台导出后追加：

| 列 | 说明 | 必填 |
|---|---|---|
| 日期 | 业务日（T+1 口径：今日导昨日） | ✅ |
| 渠道 | 天猫/京东/拼多多/猫超/即时零售/直播/私域（与日报表同字典） | ✅ |
| 店铺 | 与渠道 sheet 店铺名一致 | ✅ |
| SKU编码 | 对接 WDT spec_no（品牌/品名自动关联的键） | ✅ |
| 商品名 | 展示用 | ✅ |
| 品牌 | 分品牌榜的分组键 | ✅ |
| 销量 | 件数 | 建议 |
| 销售额 | 元（与渠道日报同口径） | ✅ |
| 推广费 | SKU 级（能导则填，不能导留空） | 可选 |

> 口径锚点：销售额与渠道日报表同来源同口径（店铺后台导出值），
> 不与 WDT 订单对照（09-22 已实测两口径不一致，废弃派生路线）。

### 1.2 仪表盘三视图（alidocs 拖拽配置指引）

指标统一定义：
- **累计销售额** = 本月 1 日至昨日合计（T+1，与日报同节奏）
- **昨日销售额** = 最近一个业务日
- **环比** =（昨日 − 前日）/ 前日 %，前日为 0 或空 → `--`

| 视图 | 配置 |
|---|---|
| ① 热销商品排名总榜 | 明细表按「累计销售额」降序 Top 50；列：SKU/商品名/品牌/渠道/累计/昨日/环比 |
| ② 分品牌热销榜 | 「品牌」分组 → 组内按累计降序；组显示品牌累计小计 |
| ③ 分渠道热销榜 | 「渠道」分组 → 组内按累计降序；组显示渠道累计小计 |

每月 1 日重置累计（仪表盘按"本月"过滤视图，或 sheet 按月分表，
由业务侧选维护成本低的）。

## 2. 电商渠道日报播报（机器人，与杭绍同形）

### 2.1 时刻表（对齐杭州/绍兴）

| 时刻 | 内容 | outbox kind |
|---|---|---|
| 08:30 | 电商渠道日报（三段，见 §2.2） | `leaderboard` |
| 18:30 | 未填提醒（@未填人员） | `remind` |
| 20:00 | 未填催办 + DING | `check` / `ding` |

管线复用 `robot-qudao`（已随 6 区域管线就位），region 配置已发 Nacos。

### 2.2 08:30 播报三段式

```text
### 📊 电商渠道日报（M月D日 周X）
时间进度 XX.X%（n/N 工作日） · 整体任务完成率 XX.X%      ← ③任务进度（杭绍同款头部）

【渠道日销】全渠道昨日销售额：XX.X万                        ← ①旧播报原样保留
| 渠道 | 销售额 | 环比 | 目标 | 达成率 |
| 天猫 | … | +x.x% | … | … |
（数据源：fact_channel_daily_sales；格式与旧 channel_report
 build_markdown 逐字复刻，含"数据来源"行改为"店铺后台导出 · DB"）

【人员完成率榜】                                            ← ②新增（杭州同构）
| 排名 | 人员 | 累计/目标 | 完成率 | 进度差/预计月末 |
（数据源：fact_daily_report_offline(qudao)，归属口径沿用
 extract_ecom_people：整店归集合每人、一人多店按日聚合；
 月目标 = Nacos region-qudao.yaml monthlyTargets）
```

①②③ 一条消息发完；①的字段口径与旧播报完全一致（红线：旧功能不变）。

## 4. 风险与注意

1. **SKU 与渠道日报口径一致性**：SKU sheet 与渠道 sheet 都来自店铺后台，
   同一导出动作里产出可避免两表对不上；T1 模板里注明"同一后台同一日"。
2. **人员归属变更**：店铺→负责人集合变动后，历史日期的归属不按新映射
   重算（快照口径，与现行 extract_ecom_people 一致）。
3. **月目标未给期间**：播报只少进度行，其余正常（不阻塞 T3）。
