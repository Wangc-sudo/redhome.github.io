# 去 AI 表格方案：DB 为唯一可行源

状态：草案（2026-09-22，运维定调"去表格化"后补记）
关联：`阶段4切换运行手册.md`（月目标迁出 AI 表）、`2026-09-22-cloud-cutover-log.md`、
`common/gateway/report_intake.py`（Stream 报数落库）、`common/region_config.py`（monthlyTargets）

---

## 1. 目标

**钉钉 AI 表格从"填报入口 + 数据读取源"降级为"过渡展示/存档"，最终下线；
填报、未填判定、月目标、榜单数据全部以 DB（mart_ops）为唯一可行源。**

判据：机器人全部业务流程（报数 → 落库 → 未填判定 → 催报 → 榜单）在 AI 表
不可达时仍完整可用。

## 2. 现状盘点（2026-09-22 实测）

| region | AI 表角色 | 去表难度 |
|---|---|---|
| vanke | **已无表**（报数 Stream 落库 + 月目标走 Nacos `monthlyTargets`） | ✅ 已完成，即目标形态 |
| hangzhou | 填报入口 + 未填判定读取源（tableUrl 真值已登记） | 中：填报习惯迁移 + 月目标迁移 |
| shaoxing | 同 hangzhou（tableUrl 真值已登记） | 中：同 hangzhou |
| junpin | 有表（URL 已登记），但机器人链路未上线 | 低：**直接无表启动**，不建依赖 |
| qudao | 无日报表（渠道维度走 WDT 数据） | ✅ 天然无表 |
| offline_all | 有表（URL 已登记），机器人链路未上线 | 低：直接无表启动 |

关键事实：去表所需的组件**今天已全部就绪**——

- 填报：`report_intake.handle_report`（群里 @机器人 报数 → 解析金额 → 门禁
  （dim_robot_member 成员校验）→ 工作日校验 → 落 mart 表 + 月目标快照 → 回执
  含累计/目标/完成率），与 listener 口径逐字一致
- 未填判定：`mart_tasks.run_remind/run_check`（名单来自 DB 成员表，不读 AI 表）
- 月目标：Nacos `region-<region>.yaml` 的 `monthlyTargets`（表内用名 → 金额，
  报数落库时快照进事实行，口径与 AI 表行携带目标等价，手册 §4 已锁定）
- 身份：`dim_robot_member` 全量通讯录（T7 已验收 91=91）
- `tableUrl` 在新架构中仅剩"催报消息里的点击链接"一个用途（`mart_tasks.py`），
  不承载任何数据链

## 3. 目标架构

```
填报：群里 @机器人 报数 ──Stream──▶ gateway（单连接按群路由）
                                     │ report_intake
                                     ▼
                            mart_ops.fact_daily_report_offline
                            （含 monthly_target 快照）
未填判定：dim_robot_member（在职全集） − 当日已报（DB）→ 未填名单
月目标：Nacos monthlyTargets（运维白屏维护，后续 ops-web 阈值编辑收口）
榜单/报表：mart_cli leaderboard 从 mart 出数（现网已是）
AI 表：只读存档（过渡）→ 下线
```

## 4. 分区域路径

**P0 已完成**：vanke（无表运行中）。

**P1 新区域直接无表启动**（junpin / qudao / offline_all）：
- 不建 AI 表依赖，填报入口第一天就是群里 @机器人
- junpin/offline_all 已登记的 tableUrl 保留在 Nacos 仅作展示链接，
  不作为填报要求（催报文案不落"请填表"口径，走 `build_format_hint` 的
  "@提醒事项 数字"口径）
- 前置：区域业务流程接入调度（remind/check 任务定义，随阶段4后排）

**P2 hangzhou / shaoxing 迁移**（有填报习惯，需谨慎）：
1. 当月月目标从 AI 表迁入 Nacos `monthlyTargets`（手册既定动作，切换前必做）
2. 双轨 1 周：群里 @机器人 报数与填表并行，机器人每日播报两边一致率
   （DB 报数落库 vs notable 读表核对）
3. 官宣切换：催报文案改为 @机器人 口径，AI 表改只读（权限收紧）
4. 观察 2 周无回补诉求 → 表下线（或留只读存档）

**P3 表格终态**：四张表全部只读存档或删除；`tableUrl` 字段从 region 配置
降级为可选（代码已容忍任意字符串，无需改）。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 填报习惯反弹（有人只认表格） | P2 双轨期 + 每日一致率播报；切换后表格只读，填了也不算（回执文案引导） |
| 月目标迁错 | monthlyTargets 快照进事实行，改目标只影响改后日期；迁移日人工核对当月完成率 |
| 多人同时报数/改数 | 落库按 (region, member, date) 覆盖写，回执显示旧值（build_recorded_reply 已有 old_value），审计可查 |
| notable 读取链退役后的遗留 | 杭州/绍兴老 config 的 baseId/tableId 随旧 listener 一并退役（手册 §5 已列） |

## 6. 里程碑建议

| 里程碑 | 内容 | 依赖 |
|---|---|---|
| M1 | junpin/qudao/offline_all 无表启动（业务流程接入调度） | 阶段4 gateway 上机 |
| M2 | hangzhou/shaoxing 月目标迁 Nacos + 双轨播报 | 阶段4 切换窗口内 |
| M3 | hangzhou/shaoxing 官宣切换 + 表只读 | 双轨一致率 ≥99% 连续 1 周 |
| M4 | 表格下线 + `tableUrl` 字段降级可选 | M3 后 2 周 |

## 7. 群公告（切换时直接复制发送）

> 写法约定：面向填报人，零技术词；`@日报小机器人` 按各群实际机器人名替换；
> 公告只讲"怎么做变了"，不讲系统。每个区域发对应一条。

### 7.1 P1 新区域启用（junpin / qudao / offline_all）

```text
📢 日报报数方式说明

以后每天报数不用填表了，直接在这个群里发：
@日报小机器人 金额

比如：@日报小机器人 12800
当天没销量就报 0。

发完机器人会马上回复你今天的累计和完成率，
看到回复就是报成功了。每天 18:00 前记得报～
```

### 7.2 P2 双轨期（hangzhou / shaoxing）

```text
📢 报数新方式试用（一周）

即日起报数有两种方式，任选其一：
1️⃣ 群里直接发：@日报小机器人 金额（推荐，机器人秒回确认）
2️⃣ 照常在表格里填

两种方式效果一样，后台会自动核对。
一周后我们将只保留群里报数，表格会停用填写，请大家提前适应～
```

### 7.3 P2 官宣切换（hangzhou / shaoxing，双轨一周后）

```text
📢 表格停用通知

从明天起，日报表格停止填写，报数只认群里发：
@日报小机器人 金额

机器人回复了才算报上，没收到回复就重发一次。
表格还可以打开看历史数据，但再填不计数。
当天没销量报 0，18:00 前完成～
```

### 7.4 P3 表格下线（可选，视存档决定）

```text
📢 日报表格下线

旧日报表格已正式停用并关闭。
每天的报数、累计、完成率直接在群里 @日报小机器人 查询和报送。
历史数据已完整保留在系统后台，需要查历史找管理员。
```
