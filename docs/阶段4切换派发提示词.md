> - **§0** = 决策背景（已定稿，执行 agent 无需再争）
> - **§A** = 可复制执行提示词（唯一要派发的内容）
> - **§B** = 明确不动（本次切换）
> - **§C** = 人工闸口（agent 必须停下等运维的步骤）
> - **§D** = 事实锚点表
> - **§E** = 一句话总结

## §0 决策背景（已定稿）

| # | 决策 | 结论 |
|---|---|---|
| 1 | 代码状态 | 阶段 4 代码侧已全部就绪并测试（448 例），本提示词**不含任何编码任务** |

| 5 | 唯一口径真源 | `docs/阶段4切换运行手册.md`（步骤语义）+ `docs/阶段4切换执行checklist.md`（逐条执行单） |

## §A 可复制执行提示词

> 复制以下整段给执行 agent。

````text
你是 ops-agent。任务：执行 digital-ops 阶段 4 切换（日报机器人从 Windows 本机 cron
旧链路切到 Docker 容器化链路）。这是运维任务，不是编码任务——代码已全部就绪，
你的职责是按 checklist 逐步执行、逐项验收、如实记录，遇失败按回退点回退。

【契约来源，先读】
1. docs/阶段4切换执行checklist.md（逐条执行单，你的主任务表）
2. docs/阶段4切换运行手册.md（每步的原理、口径与注意事项）
3. docs/superpowers/specs/2026-09-10-three-lines-docker-decomposition.md（三线全景）
4. docker-compose.integration.yml（各 profile 的命令与挂载约定）

【先确认的三件事，动手前必须回答】
Q1 现状确认：现网桌面端 cron 5 个任务是否仍在启用？robot_outbox 表近期是否有
   delivered 行？Nacos REGIONS 组是否已有真值？——三项证明「当前仍是旧链路」
   才能开始；若显示已部分切换，停下来向运维报告实际状态，不要假设。
Q2 凭据就位：仓库外的真值 region JSON、manifest、source-credentials.json 三个
   文件的实际路径是什么？向运维索取，不存在就停，不伪造、不用种子占位符冒充真值。
Q3 窗口确认：本次窗口覆盖 checklist 的哪几步？第 4 步「观察 2 个工作日」和第 5 步
   「回退窗口结束（建议 1 周）」意味着本任务必然跨多个窗口——与运维约定每个窗口的
   起止步骤，单窗口内绝不越过约定边界。

【铁律（违反即返工）】
1. 顺序不可逆：严格按 checklist 第 0→6 步执行，不跳步、不并行、不合并窗口。
2. 验收不过即停：任何一项验收失败，原地停下，执行该项回退动作，向运维报告
   失败证据（日志/截图/SQL 结果），等人工决策，不自行重试超过一次。
3. 双跑期不动旧链路：第 2/3/4 步期间，现网 cron 与其脚本一字不动；第 4 步
   验收通过前不注释任何 cron 项。
4. 凭据零入库零入仓：真值文件只在仓库外路径引用；命令历史、日志、plan 文档中
   出现真实 robotCode/conversationId/AppSecret 时必须脱敏。
5. 退役步骤逐 commit：第 5 步每删一个文件/机制单独 git commit，消息写清对应
   checklist 项号，保证逐项可 git revert。
6. 文档收尾不省：第 6 步 README 两处更新（运行方式、尚未实施清单）与 checklist
   同步完成，防止文档再次与现实脱节。

【人工闸口——到点必须停下等运维，不得自行通过】
G1 第 0 步完成后：预检结果汇报运维，拿到「窗口开始」确认再进第 1 步。
G2 第 1 步发布前：真值文件由运维提供并目视确认（你只核对 schema 与字段完整性）。
G3 第 3 步真群测试：发消息动作由运维在测试群执行，你负责观察回执与落库并判定验收。
G4 第 4 步注释 cron：两个工作日观察期满、robot_outbox 全 delivered 后，
   由运维亲手注释现网 cron（你提供清单与命令，不代劳）。
G5 第 5 步开始前：回退窗口（默认 1 周）结束且无回退发生，运维确认后才动旧脚本。

【执行方式】
- 每个 checklist 项完成后立即在打勾副本上标记（含时间戳与证据链接/行号）。
- 所有 docker compose 命令严格使用手册中的原样格式；环境变量按 profile 要求注入。
- 双跑对照的所有数字（行数、record_id_digest、榜单输出 diff）原样记录，不做
  「差不多就行」的口头通过。
- 发现手册/代码/现实三方任何不一致：以现实为准，停下来登记，等运维裁决，
  不为了推进而改代码或改文档。

【汇报要求】
新建 docs/superpowers/plans/2026-09-21-stage4-cutover-log.md（逐窗口追加），记录：
  - Q1/Q2/Q3 的回答与确认人；
  - 每步验收证据（sync_runs 状态、行数对照表、回执截图说明、cron 注释 diff）；
  - 每次回退演练的实测耗时；
  - 所有偏差登记（文档 vs 现实的任何出入）；
  - 第 5 步每个删除 commit 的 hash 与对应 checklist 项号。
任务完成 = checklist 第 6 步全部打勾 + log 文档完整 + 运维签字确认。
````

## §B 明确不动（本次切换）

| 对象 | 为什么不动 |
|---|---|
| `common/**` 任何代码 | 代码已就绪并通过 448 例测试，本任务是纯运维切换；发现代码问题 → 登记偏差开新任务 |
| 现网 cron 脚本内容 | 旧链路是回退保底，双跑期内一字不动 |
| `docker/integration/*.seed.*` | 种子保持占位符语义，真值只进 Nacos |
| 测试库以外的任何数据库 | 生产库切换属上云部署规划范围，不在本批 |
| BI-web / 播报线 | 各有独立 spec 与计划，不搭车 |
