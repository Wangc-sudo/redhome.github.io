## 三、本次整改的三处变更

1. **取证能力缺失 → 显式跳过（不是静默降级）**
   `IntegrationEnvironmentContractTests` 增加第二道 `skipIf`：`docker` CLI 不在
   PATH 时跳过，跳过理由写明「契约由 CI 的 `compose-contracts` job 强制执行」。
   需要完整校验的环境（发布前自检）设 `INTEGRATION_CONTRACT_REQUIRED=1`，
   此时 CLI 缺失直接失败。

2. **闸门补强（补偿控制）**
   CI 新增 `compose-contracts` job：在 **docker 主机上**（不在 test-runner 容器内）
   以 `INTEGRATION_CONTRACT_REQUIRED=1` 跑 `tests/test_integration_environment.py`，
   并纳入 `gate` 的 `needs`。此前这类契约在 CI 里恒被跳过 = 无闸门；现在每
   个 PR 都真跑。

3. **防复发静态契约**
   新增 `ComposeReferenceContractTests`：纯文件读取、任何环境可跑（含容器内），
   钉住「编排声明的模块必须存在」。拆分时删了模块却没删编排的那种事故（本次
   `pages_web` 即此类）会先在这里红，而不是在部署健康门回滚时才暴露。

> 说明：这三处改动都未放宽任何安全断言——`credential-free`、`read-only`、
> `loopback-only`、opt-in profile、「凭据透传且默认为空」等断言逐条保留。

## 五、发布 / 回滚清单

本次改动只碰测试 + CI + 文档，**不动 compose 与部署脚本**，因此发布面为零：

1. 合并前确认 CI 五项（含新增 `compose-contracts`）全绿。
2. 合并后观察首个 `ops/deploy.sh` 周期：`DEPLOY OK` 与 `health_gate` 通过即可，
   本次没有会改变运行态的内容。
3. 若 `compose-contracts` 在 CI 上异常失败（例如 runner 缺 docker compose v2），
   先看 `docker compose version` 输出；该 job 只读、不创建容器，失败不会污染
   CI 环境，可用 `workflow_dispatch` 单独重跑诊断。
4. 回滚：删除该 job 的 `needs` 条目即可恢复原状（测试侧的显式跳过可独立保留）。
