## 你的任务

在钉钉卡片搭建平台为小易（公司知识库问答机器人）创建并发布一个**自建互动
卡片模板**，使商品答案能以「图片+参数+可点按钮」的卡片形态发送，且按钮
点击能回调机器人发附件。

**完成后只需交付一样东西：cardTemplateId**（形如 `xxxxxxxx-xxxx-xxxx.schema`），
发给开发侧即完成交接。

## 背景三分钟版

- 小易是钉钉机器人（客服群里答商品/手册问题），独立应用，AppKey
  `dingnbp9wl6mt54n89hj`。
- 我们要把「单款商品命中」的回答升级为卡片：商品图 + 名称 + 参数 +
  三个按钮（发我细节图 / 发我质检报告 / 发我图片素材）。
- 已实测的硬约束：钉钉 SDK 内置公共卡片的按钮**只能跳链接、点了没回调**，
  所以必须自建模板；自建模板的按钮选「回传请求」才能把点击事件传回机器人。
- 回调通道已就绪（与问答消息共用同一条长连接，不需要公网地址/不用开
  任何端口）。**你不需要懂回调实现，只要按本单配按钮。**

## 执行步骤

### 第 1 步：开通权限（开发者后台）

1. 打开钉钉开放平台开发者后台，找到小易应用（AppKey
   `dingnbp9wl6mt54n89hj`）。
2. 权限管理 → 搜索「卡片」→ 开通 **Card.Instance.Write**（写卡片实例）。
   如需组织管理员审批，走审批。

### 第 2 步：建模板（卡片平台）

1. 打开 <https://card.dingtalk.com>，用小易应用所属账号登录。
2. 新建卡片模板，命名「小易商品资料卡」。
3. 布局：自上而下 = 商品图（绑变量 `image`）→ 标题（绑 `title`）→
   markdown 正文区（绑 `params_md`）→ 按钮组。
4. 创建模板变量（发卡时由代码注入值）：

   | 变量名 | 类型 | 用途 |
   |---|---|---|
   | `title` | 文本 | 商品名 |
   | `image` | 图片 | 商品主图 URL |
   | `params_md` | markdown | 参数正文 |
   | `record_id` | 文本 | 商品记录 ID（按钮回传用，不展示） |

### 第 3 步：配按钮（最关键，逐字核对）

三个按钮，**交互行为全部选「回传请求（request）」——不要选「跳转链接」**
（跳转链接点了不会通知机器人，这是本方案的红线）。

| 按钮文案 | privateData（回传负载，照抄） |
|---|---|
| 📷 发我细节图 | `{"kb_action":"asset","field":"细节图","record_id":"${record_id}"}` |
| 📄 发我质检报告 | `{"kb_action":"asset","field":"质检报告","record_id":"${record_id}"}` |
| 🖼 发我图片素材 | `{"kb_action":"asset","field":"图片素材","record_id":"${record_id}"}` |

- `${record_id}` 必须绑到第 2 步的模板变量（平台 privateData 配置里选变量
  插值），这样代码发卡时填什么，点击就回传什么。
- `kb_action` / `field` 是固定字面值，逐字照抄，不要翻译不要改键名。

### 第 4 步：发布并交付

1. 模板发布（上线）。
2. 把 **cardTemplateId** 发给开发侧（格式形如 `xxx-xxx.schema`）。
3. 顺带把模板预览截图发群里存档。

## 验收（开发侧接线后共同验证）

1. 客服群 @小易 问「习酒窖藏1988 箱规」→ 收到卡片（图+参数+按钮）；
2. 点「📄 发我质检报告」→ 群里收到文件，卡片按钮区显示「已发送」；
3. 无附件商品点按钮 → 卡片如实提示「该商品暂无此附件」。

## 边界与求助

  全部由开发侧完成。
- 平台 UI 找不到「回传请求」或 privateData 变量插值入口 → 截图发给开发侧

- 参考资料：《规格单》（同目录）；PoC 结论与回调报文结构在
